## 2. 静态稿

位置：`可视化页面/静态稿/`。交付形态是可点击的静态原型，不是应用。

### 2.1 结构

- **每个状态一个独立 HTML 页面**，放在 `screens/`。一个页面只呈现一个 360×800 的应用界面。
- `index.html` 是总览：按页面分组，列出每个状态入口，并显示「6 个页面 / 37 个状态」这类计数。
- `assets/spec.css` 存放全部令牌与组件样式；页面不写自己的主题色。
- `tools/build.py` 是可选生成脚本；交付物不依赖它。

### 2.2 硬规则

- **纯 HTML + CSS，不引入 JS。** 不要写 `<script>`、事件监听、自动状态推进。原型靠 `<a href>` 跳转。
- **不套手机外框。** 页面里只有 360×800 的应用界面（`.frame` 是视口容器）；不加系统状态栏、Home 指示条、设备边框、背景阴影。
- **单页单状态。** 不要把多个状态并排放在同一页，也不要用同一页面内的切换模拟状态。
- **链接必须可达。** 主按钮、列表行、TabBar、Sheet 按钮都指向对应单页；没有对应页时就指回合理的上一级，不要留 `href="#"` 死链。
- **新增状态要四处同步**：`screens/` 新页面、`index.html` 入口与计数、`静态稿/README.md` 的状态表、`../UI设计说明.md` 对应页面的状态表。
- **图标用内联 SVG。** 24 网格、`stroke-width: 1.75`、`stroke: currentColor`、圆头圆角；优先复用页面里已有的 `<symbol>`，不要引入图标库或 emoji。
- **示例数据只用于展示。** 规范里给出的值照用；规范没给的值（点位名称、消耗 kcal、部分坐标）可以用，但要在 `静态稿/README.md` 说明「仅用于展示，不代表真实接口数据」。
- **长页面按视口截取。** 规则页点位、配置页图表、运行日志等，按 360×800 的指定滚动位置呈现；不要为了塞内容缩小字号。

### 2.3 视觉

- 深色任务控制台：近黑底、细描边、数据密度偏高，但每张卡片只讲一件事。
- 标题 16、正文 14、辅助 12；不靠字重堆层级。
- 少圆角；不用大面积渐变、发光、玻璃拟态、装饰性渐变球。
- 图表与轨迹用静态 SVG；规则上下限用 `--warn` 虚线；不实现 tooltip 或缩放交互（按钮可以是死链接）。
- 按钮、输入、Chip、Switch 的视觉尺寸与命中尺寸分开：Chip 视觉 36、命中 44；Switch 48×28 但外层命中区要够 44。

### 2.4 修改现有页面的顺序

1. 读目标页 + 同组相邻页 + `UI设计说明.md` 对应页面 + `UI_SPEC.json` 对应 `screens[]` 条目。
2. 确认这次改动是否已被 `静态稿/README.md` 的「设计变更」覆盖。
3. 只改必要结构；复用已有 class 和 SVG symbol。
4. 如果新增/删除状态，同步 `index.html`、README 状态表、`UI设计说明.md` 状态表（四处同步）。
5. 跑 `scripts/check_static.py` 和 `scripts/check_docs.py`。
6. 判断是否需要写思维链（见 `SKILL.md` §4）。

## 3. Vue3 工程

> 当前仓库还没有 `app/`。以下是 M0 之后的目标结构，不要在骨架存在前假装它已经存在。实际路径以 `AI_SPEC.json` 的 `repoLayout` 和 M0 落地结果为准。

### 3.1 技术约束

- Vue 3.5 + TypeScript + Vite 7 + Pinia 3 + Vue Router 4。
- 路由用 **hash 模式**，避免 WebView 深链问题。
- 页面放 `src/pages/`，组件放 `src/components/`，store 放 `src/stores/`，桥接封装放 `src/native/`。
- 单文件组件用 `<script setup lang="ts">`，组件名 PascalCase，页面名以 `Page.vue` 结尾。
- 样式令牌放 `src/styles/tokens.css`，与 `静态稿/assets/spec.css` 同源；组件里用 `var(--token)`，不写死颜色。
- 不使用外部字体、CDN、统计、崩溃上报；系统字体栈与静态稿一致。

### 3.2 路由与守卫

- 路由守卫至少覆盖：`auth`（需要登录）、`activeRun`（运行中页）、`hasResult`（结果页）。
- 未登录访问受保护页 → 回登录页；运行中离开 → `ConfirmSheet`；结果不存在 → 回跑步首页。
- 路由切换不要用花哨转场；这是工具，不是展示型 App。

### 3.3 状态与桥

- 所有原生调用只经过 `src/native/protocol.ts`；不要在组件里直接碰 `window` 上的桥对象。
- 浏览器开发用 `src/native/mock.ts` 返回稳定假数据；mock 不能进入生产包，也不要把 mock 数据当成真实接口契约。
- Pinia store 按 `auth` / `policy` / `run` / `device` / `ui` 拆分；服务端状态不要在多个组件里各自复制。
- 事件（`runProgress`）进入 run store，再由阶段进度和日志组件消费；不要在多个组件里各自订阅。
- 错误统一映射：桥返回错误码 → `errorHandling` 文案 → `ErrorPanel`；不要把原始异常、堆栈、URL 直接展示给用户。
- 敏感值（token、密码、盐、验证码 ID）只存在于安全存储或内存会话，不写进前端常量、日志、埋点。

### 3.4 页面实现

- 每个数据区块都要有 `loading / empty / error / partial` 四态；没有数据的正常态也要有明确文案。
- 危险动作（提交、清除会话、取消运行、离开运行页）一律走 `ConfirmSheet`；提交按钮附近必须写「会写入服务器」这类后果说明。
- 固定操作栏要避开安全区；主操作在底部 1/3 屏幕内。
- 图表用 ECharts 或静态 SVG，按 `chartTheme` 令牌；轨迹用自绘 SVG，不用真实地图瓦片。
- 数字、文案、状态遵循 §4。

## 4. 数字、文案与状态

### 4.1 数字

- 所有数字用等宽字体 + `font-variant-numeric: tabular-nums`。
- 配速：`5'53"/km`（分 + 秒 + 引号 + `/km`）。
- 距离：展示 2 位小数（`3.02 km`），输入 1 位小数（`3.0`）。
- 时长：`mm:ss`；超过 60 分钟时用 `h:mm:ss`，同一屏保持一致。
- 单位永远紧跟数值，不单独换行；同一列数字对齐小数点。
- 不要四舍五入到看不出差异：有效/无效的边界值要保留原始精度。

### 4.2 文案

- 唯一来源：`UI_SPEC.json` 的 `screens[].copy`、`copyDeck`、`errorHandling`、`errorCodes`。
- 不改写按钮、错误标题、提示语；不把「失败」软化成「有点问题」。
- 新文案先标「待确认」，并在回复里说明为什么现有文案不够。
- 错误显示要区分：可重试 / 不可重试 / 未知。回查失败必须显示「未知」，不能显示「成功」。

### 4.3 状态

- 四态：`loading / empty / error / partial`。
- 状态表达：图标 + 文字 + 颜色，三者同时出现。
- 部分失败（partial）要说清「哪些成功、哪些失败、还能不能继续」。
- 运行中要显示当前阶段、已完成阶段、能否取消；OBS 开始后取消要禁用。
- 未知状态不要猜。宁可显示「未知，请回查」，也不要显示一个看起来合理的结论。

## 5. 可访问性

- 所有触摸目标 ≥ 44×44 dp；视觉可以更小，但命中区要补足。
- 图标按钮必须有 `aria-label`；装饰性 SVG 加 `aria-hidden="true"`。
- 图表/轨迹容器加 `role="img"` 和描述性的 `aria-label`（说明画的是什么、范围、关键标注）。
- 正文与背景对比度至少 4.5:1；弱文字只用于辅助信息，不承载关键结论。
- 不依赖颜色单独传达状态；不仅靠 hover 触发操作（这是触屏原型）。
- 键盘/读屏顺序与视觉顺序一致；弹层出现时焦点进入弹层，关闭后回到触发点。
- 支持系统字体放大到 200% 时，关键页面不横向滚动、不截断主操作。

## 6. 禁止项

这些做法在这个项目里会破坏一致性或误导用户：

- 在静态稿里加 JS、框架、构建步骤、自动状态推进。
- 用 emoji、图标字体、外部图片代替内联 SVG。
- 大面积渐变、发光、玻璃拟态、装饰性渐变球、重阴影。
- 大圆角胶囊按钮、把卡片做成 iOS 小组件风格。
- 硬编码颜色/圆角/间距；绕过 `spec.css` / `tokens.css`。
- 自行发明文案，或把 `errorCodes` 改写成更「友好」但含义不同的说法。
- 把示例数据写成真实数据，或声称静态稿已经接了接口。
- 用颜色单独表示成功/失败；用「成功」表示「回查未知」。
- 为了省事把多个状态塞进一页，或删掉 `loading/empty/error/partial` 中的某态。
- 引入外部字体、CDN、统计、崩溃上报、自动更新脚本。
