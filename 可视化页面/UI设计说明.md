## 1. 信息架构

### 1.1 页面地图

```text
冷启动
 └─ /login                     登录（全屏，无 Tab）
      │
      └─ 登录成功
          ├─ /             跑步（首页）        [Tab 1]
          │    ├─ /run/running   运行中（全屏，压栈）
          │    └─ /run/result    跑步结果（全屏，压栈；含演练结果）
          ├─ /policy       规则与围栏          [Tab 2]
          └─ /me           我的                [Tab 3]
                           └─ 待重试任务 Sheet
```

### 1.2 路由表

| 路径 | 页面 | 布局 | 需登录 | 守卫 | 主要入口 |
|---|---|---|---|---|---|
| `/login` | 登录 | fullscreen | 否 | — | 冷启动无会话、会话过期确认后、清除会话后 |
| `/` | 跑步（首页） | tabs | 是 | `auth` | 登录成功、Tab 1、结果页返回 |
| `/policy` | 规则与围栏 | tabs | 是 | `auth` | Tab 2 |
| `/me` | 我的 | tabs | 是 | `auth` | Tab 3 |
| `/run/running` | 运行中 | fullscreen | 是 | `auth` + `activeRun` | 真实提交、演练开始、重试提交 |
| `/run/result` | 跑步结果 | fullscreen | 是 | `auth` + `hasResult` | 运行结束、取消、失败、演练完成、重试完成 |

- 结果页同时承载真实跑步结果与演练结果；不新增独立的「演练结果」页面。
- 重试提交可以从结果页或「我的」发起；运行中页只展示本次重试的进度，不改变页面归属。

### 1.3 Header 与 TabBar

**Header**

- 标题左对齐；全屏页左侧为返回，Tab 页无返回。
- 右侧最多 1 个图标动作或 1 个文字动作。
- 滚动时保持不透明，不做毛玻璃。
- 本文件不定义高度、字号等数值。

**TabBar**

- 3 项等宽：`跑步`、`规则`、`我的`。
- 选中项同时用图标、文字与顶部指示条表达，不只靠颜色区分。
- 重复点击当前 Tab：回到该页顶部。
- 运行中、结果页、登录页不显示 TabBar。

### 1.4 返回与离开

| 场景 | 行为 |
|---|---|
| 未登录访问任意受保护页 | 重定向 `/login`；登录后回跳原目标 |
| 有运行任务时离开 `/run/running` | 弹出 `ConfirmSheet`：继续运行 / 取消运行并离开；Android 返回键同样拦截 |
| 在 `/run/running` 按返回 | 不静默退出，必须先确认 |
| 登录页按返回 | 二次确认后退出 App |
| Tab 页按返回 | 先回跑步首页；已在跑步首页再按一次退出 App |
| 结果页按返回 | 回 `/`，保留上次距离 / 时长参数与预览；清理上一次的结果 / 阶段 / 日志；主按钮恢复可用；不自动重新预览 |
| 演练结果页按返回 | 回 `/`，保留参数；清理本次演练结果；不自动重新预览 |
| 运行中结果未知 | 仍进入结果页，Hero 显示「状态未知」，不得显示成功 |
| 待重试任务 Sheet 按返回 | 关闭 Sheet，留在「我的」 |

## 2. 全局页面规则

### 2.1 页面状态

| 态 | 表达 | 规则 |
|---|---|---|
| Loading | 骨架 / 按钮 loading / 进度条 | 骨架尺寸与真实内容一致；超过 400ms 才显示骨架，避免闪烁 |
| Empty | `EmptyState` | 说明「为什么空」+ 下一步动作 |
| Error | `ErrorPanel` | 人话标题 + 错误码 + 可重试动作；`detail` 默认折叠 |
| Partial | 区块级错误 + 其余正常 | 一个区块失败不拖垮整页；档案鉴权失败除外 |
| 进行中 | 进度条 / 阶段文案 / 按钮 loading | 路线规划、OBS 上传、轨迹回读、重试提交都使用同一套进行中表达 |

### 2.2 危险动作与确认

- 真实提交、重试提交、取消运行、离开运行页、清除会话、导出记录 / 轨迹，全部经过 `ConfirmSheet`。
- 真实提交与重试提交附近必须明确写出「会写入服务器」。
- 重试提交必须说明「使用同一任务，不会重复生成记录」。
- 危险确认默认不聚焦主按钮。
- 演练不写服务器，不弹提交确认；演练结果进入结果页后，导出仍需确认。

### 2.3 文案与术语

- 短句、动词开头、给出下一步；不用感叹号，不卖萌，不指责用户。
- 说事实与后果，例如「提交后会写入服务器，且无法撤销」。
- 中文与数字之间留一个空格：`3.0 km`、`5 个点位`、`12 个点`。
- 文案唯一来源：本文件的各页面「文案」段。新增文案先写进本文件，再进入视觉稿或实现。
- 术语：

| 用词 | 含义 | 不用 |
|---|---|---|
| 会话 | 本机保存的登录状态 | 登录态、session |
| 凭证 | token 的界面称呼 | 密钥、密码 |
| 围栏 | 学校电子围栏 | 地理围栏、geofence |
| 点位 | 官方必经打卡点 | 五点、checkpoint |
| 回查 | 向服务器再次确认成绩记录 | 复查、校验 |
| 结算 | 提交成绩并得到服务器记录 | 上报、保存记录 |
| 演练 | 只生成并校验轨迹，不写服务器 | 测试、模拟 |
| 轨迹 | 本次生成的跑步路线与采样点 | 路径、track |
| 避建筑路线 | 固定使用的路线规划方式：在围栏内、避开校园建筑、经过官方点位 | OSM、A*、栅格、算法路线 |
| 轨迹回读 | 从服务器存储中重新读回刚上传的轨迹，确认可解析 | OBS 验证、对象校验 |
| 待重试任务 | 已保存在本机、尚未完成提交的跑步任务 | outbox、失败队列 |
| 有效 / 无效 / 未知 | 跑步记录有效性三态 | 达标 / 不达标 / 未定 |
| 已验证 / 未验证 / 回读失败 | 轨迹上传后的回读状态 | 上传成功 / 上传失败（仅用于 OBS 行） |

- 长度：按钮 2–4 个汉字；页面标题 4 个汉字以内；Toast ≤ 24 个汉字；错误标题 ≤ 12 个汉字，说明 ≤ 40 个汉字。

### 2.4 数字格式

| 类型 | 格式 | 示例 |
|---|---|---|
| 配速 | `m'ss"/km`，秒补零 | `5'53"/km` |
| 距离（输入） | km，1 位小数 | `3.0 km` |
| 距离（展示） | km，2 位小数 | `3.02 km` |
| 时长 | `mm:ss`；≥1h 用 `h:mm:ss` | `17:40` / `1:02:33` |
| 时间戳 | 本地 `HH:mm:ss` | `14:03:12` |
| 坐标 | 6 位小数 | `30.123456, 120.123456` |
| 百分比 | 整数 | `62%` |
| 轨迹点数 | 整数 +「个点」 | `408 个点` |

- 数字统一等宽；负号用 `−`（U+2212）。

### 2.5 路线规划规则

- UI **固定使用避建筑路线**，不提供「合成 / 避建筑」来源选择，也不提供校园选择。
- 路线必须同时满足：在电子围栏内、避开校园建筑、经过官方下发的全部点位、按目标距离与时长采样。
- 当前校园数据固定为许昌学院；预览区与结果页显示数据署名。
- 预览只生成、不上传、不写服务器；真实提交会重新生成一份提交内容，不复用预览结果。
- 规划失败直接显示错误，不静默回退到直线连接，也不假装成功。
- 多区域学校暂不能在 UI 选择区域（GAP-02）；路线使用当前选中的围栏与点位，界面必须让用户知道当前用的是哪一个围栏。
- 路线规划属于「进行中」操作，可能需要等待；等待期间主按钮禁用，并显示明确的规划中状态。

### 2.6 上传、回读与本地任务

- 真实提交的顺序：生成本地任务 → 上传轨迹 → 结算 → 服务器回查 → 轨迹回读。
- 任一步失败都不丢弃任务；任务保存在本机，结果页和「我的」都能找到并重试。
- 重试使用同一任务标识，不重复生成新记录；如果服务器已有记录，恢复原 rrid。
- **轨迹回读失败不等于成绩无效**：有效性只来自服务器回查；回读只影响「轨迹是否可被服务器解析」这一行。
- 回查无结果一律显示「未知」，不得显示成功。
- 演练不产生服务器记录，也不产生待重试任务；演练结果只在本机展示与导出。
- 清除会话不删除待重试任务；重新登录后可继续重试。

### 2.7 视觉基线

- 沿用原控制台的视觉语言：深色背景、卡片化分组、青柠主色、少量状态色、底部固定操作区、3 个 Tab。
- 状态用图标 + 文字 + 颜色三重表达；危险动作使用确认 Sheet。
- 本文件不定义颜色、字号、间距、圆角、组件尺寸；重建视觉规范时以原风格为准，不引入新的视觉体系。
- 数字等宽；配速、距离、时长格式见 2.4。

## 3. 页面详设

> 每页固定八段：目的 / 功能清单 / 入口与出口 / 页面结构 / 交互 / 状态 / 文案 / 验收要点。
> 视觉尺寸、颜色、组件样式不在此展开。

### 3.1 登录 `/login`

#### 目的

用手机号和密码完成登录；需要时在 Sheet 内手动完成极验滑块；登录成功后由桥接自动保存会话。这是唯一没有 TabBar 的入口页。

#### 功能清单

- 输入手机号、密码。
- 显示 / 隐藏密码。
- 登录。
- 需要时打开安全验证 Sheet，完成滑块。
- 登录失败显示错误面板。
- 会话过期后显示一次性提示。
- 返回时二次确认退出。
- 不提供 token 输入、展示、复制或导入入口。

#### 入口与出口

| 类型 | 说明 |
|---|---|
| 入口 | 冷启动无会话；会话过期；清除会话后 |
| 出口：登录成功 | 替换路由到 `/`，不保留登录页历史；Toast「登录成功」 |
| 出口：退出 | 确认后退出 App |
| 出口：继续登录 | 关闭确认，留在本页 |

#### 页面结构

1. 右上版本号。
2. 品牌区：logo、标题「校园跑控制台」、副标题「CampusRun Console」。
3. 手机号输入。
4. 密码输入 + 眼睛按钮。
5. 登录按钮。
6. 自动保存提示。
7. 底部免责声明。

#### 交互

| 元素 | 操作 | 效果 |
|---|---|---|
| 手机号 / 密码 | 输入 | 清除对应行内错误；登录按钮在两项非空时可用 |
| 密码眼睛 | 点击 | 切换明文 / 密文，不改变光标位置 |
| 登录 | 点击 | 本地校验非空；需要时先打开安全验证 Sheet；提交后按钮 loading |
| 安全验证 Sheet 滑块 | 拖动 / 完成 | 成功后继续登录；失败留在 Sheet 重试 |
| 安全验证 Sheet 关闭 | 点击 | 本次验证作废，回表单 |
| 登录失败 | 自动 | 显示错误面板；保留手机号，清空密码 |
| 会话过期提示 | 自动 | 页面顶部显示一次性提示，用户开始输入后消失 |
| 返回 / 手势 | 返回 | 弹出退出确认：退出 / 继续登录 |

#### 状态

| 状态 | 触发 | 界面表现 |
|---|---|---|
| `idle` 默认 | 进入页面 | 手机号、密码、登录按钮；底部免责声明 |
| `submitting` 登录中 | 点登录 | 登录按钮 loading；输入只读 |
| `error` 登录失败 | 接口返回失败 | 错误面板：标题、错误码、可重试；保留手机号 |
| `captcha` 安全验证 | 需要验证 | 安全验证 Sheet；滑块区、提示、关闭 |
| `expired` 会话过期 | 会话失效后回到登录 | 顶部一次性提示「登录已过期，请重新登录」 |
| `exit` 退出确认 | 返回 / 手势 | 退出确认 Sheet |
| `captchaRetry` 验证失败 | 滑块未通过 | 留在 Sheet，提示重试；不关闭页面 |

#### 文案

| 位置 | 文案 |
|---|---|
| 标题 | `校园跑控制台`；`CampusRun Console` |
| 版本 | `v{version}` |
| 输入 | `手机号`；`密码` |
| 登录 | `登录` / `登录中…` |
| 自动保存 | `登录成功后，会话将保存在本机` |
| 验证 Sheet | `安全验证`；`完成滑块后继续登录`；`关闭`；`验证失败，请重试` |
| 过期 | `登录已过期，请重新登录` |
| 失败标题 | `登录失败`；`请检查手机号、密码或网络后重试` |
| 退出确认 | `退出校园跑控制台？` / `退出` / `继续登录` |
| 免责 | `本工具仅用于本人账号的协议调试与可视化展示。` / `请遵守所在学校的跑步规定。` |

#### 验收要点

- 不出现 token 输入、展示、复制或导入入口。
- 密码只在内存；登录成功、失败、离开页面时清空。
- 登录失败保留手机号、清空密码。
- 安全验证 Sheet 关闭后本次验证作废。
- 退出必须二次确认。
- 会话过期提示只出现一次。
- 视觉沿用原控制台风格，不新增登录页专属视觉体系。

### 3.2 跑步 `/`（首页）

#### 目的

一屏完成开跑前的全部确认：看学期进度、设置距离与时长、确认配速与规则、看避建筑路线与曲线、决定真实提交还是演练。

首页就是跑步页，不再有独立「控制台」；学期进度、参数、路线预览、主按钮都在这一页。

#### 功能清单

- 查看学期进度：已完成 / 目标、百分比、剩余里程、有效跑步次数。
- 查看当前跑步模式与围栏摘要。
- 设置距离：数字输入，或点 `2.0 / 3.0 / 5.0` 快捷值。
- 设置时长：分、秒两个输入。
- 查看预计配速，以及是否在规则范围内。
- 查看非阻断警告，例如「当前时间不在有效时段」。
- 查看避建筑路线预览：围栏、校园建筑、校园道路、轨迹、官方点位、起终点、比例尺、指北针、缩放按钮。
- 查看路线署名：当前校园与 OpenStreetMap 贡献者。
- 查看速度曲线、步频曲线。
- 查看签名摘要（脱敏）。
- 切换演练模式。
- 开始跑步（真实提交）或开始演练。
- 刷新页面数据或路线预览。
- 切换到「规则」「我的」Tab。

#### 入口与出口

| 类型 | 说明 |
|---|---|
| 入口：登录成功 | 进入跑步首页 |
| 入口：TabBar「跑步」 | 回到本页；重复点击回到顶部 |
| 入口：结果页返回 | 回到本页，保留上次距离 / 时长 / 预览；清理上次结果、阶段与日志 |
| 入口：规则页返回 | 回到本页；若模式或围栏变化，按新参数重新规划路线 |
| 出口：「开始跑步」 | 打开提交确认 Sheet；确认后进入运行中 |
| 出口：「开始演练」 | 不弹确认，直接进入运行中（演练） |
| 出口：Tab「规则」 | `/policy` |
| 出口：Tab「我的」 | `/me` |
| 出口：系统返回键 | 已在跑步首页时，再按一次退出 App；不回到其他 Tab |

#### 页面结构

1. **Header**：标题「跑步」；右侧在线 / 离线状态 + 刷新按钮。
2. **学期进度卡**：标题、百分比、进度条、已完成 / 目标、剩余里程、有效跑步次数。
3. **模式与围栏摘要**：模式徽标（`计分跑` / `自由跑`）+ 围栏名 · 点位数量。

**预览与提交约束**

- 预览不写入服务器：不产生 OBS、结算、回查、回读请求。

- 预览请求失败保留上一次成功预览，标记「预览已过期」，主按钮禁用。

### 3.3 规则与围栏 `/policy`

#### 目的

在开跑前看清规则边界，选择模式与围栏，加载官方打卡点。这一页是「跑步是否可能有效」的证据页。

- 切换计分跑 / 自由跑。

- 查看围栏画布与点位。

- 查看人脸抽检状态与提示。

- 切换模式会清空点位并重新加载规则；切换围栏会自动重查点位。
- 点位查询失败显示错误，不静默使用本地兜底。
- 自由跑不查询点位，但保留围栏与规则。
- 页面明确提示路线规划会使用当前围栏与点位。
- 多区域无法选择时显示待确认提示，不假装成功。
- 人脸抽检开启时提示明显，不阻断切换。
- 3 个 Tab 中「规则」高亮。

### 3.4 运行中 `/run/running`

#### 目的

让五个不可见的内部阶段变成一条可读的进度线；让用户知道现在能不能取消、什么时候不能取消、失败卡在哪一步、任务是否已保存在本机。

#### 功能清单

- 查看总进度。
- 查看 5 行阶段进度：时钟校准、规则与围栏、路线规划与校验、OBS 上传、结算与回读。
- 查看当前阶段卡：阶段说明、路线诊断、对象键、已上传字节数、rrid、回读点数。
- 查看回填时间说明。
- 查看运行日志，暂停 / 继续自动滚动。
- 取消运行（OBS 开始前可用）。
- 离开页面时确认。
- 演练完成态。
- 运行失败态。
- 运行期间保持屏幕常亮。

#### 入口与出口

| 类型 | 说明 |
|---|---|
| 入口 | 真实提交确认后、开始演练后、结果页 / 我的发起重试后 |
| 出口：成功 | 全部阶段完成，600ms 后进入结果页 |
| 出口：演练完成 | 第 4、5 阶段跳过，600ms 后进入结果页 `dryRun` |
| 出口：失败 | 当前阶段失败，进入结果页 `error` 或 `dryRunError` |
| 出口：取消 | 进入结果页 `cancelled` |
| 出口：离开确认 | 「取消运行并离开」进入结果页 `cancelled`；「留在本页」关闭确认 |
| 返回键 | 必须经过离开确认，不静默退出 |

#### 页面结构

1. **Header**：返回、标题「运行中」、右侧总进度百分比。
2. **总进度条**。
3. **阶段列表**：5 行，每行序号、标题、状态、右侧元信息。
4. **当前阶段卡**：阶段说明；路线规划阶段显示点位、建筑、路线长度、圈数；上传阶段显示对象键与字节数；结算阶段显示 rrid；回读阶段显示点数。
5. **回填说明**：仅在路线规划及以后出现。
6. **运行日志**：标题 + 暂停 / 继续 + 日志区。
7. **底部操作区**：取消运行按钮 + 说明。
8. 无 TabBar。

#### 交互

| 元素 | 操作 | 效果 |
|---|---|---|
| Header 返回 / 系统手势 | 点击 / 返回 | 弹出 `ConfirmSheet`「确定离开运行页？」；「留在本页」关闭；「取消运行并离开」进入取消流程并去结果页 `cancelled` |
| 「取消运行」 | 点击 | 弹出取消确认；确认后按钮进入「正在取消…」；等待当前阶段结束 |
| 「取消运行」（OBS 已开始） | — | 按钮禁用；说明「轨迹上传开始后无法取消」 |
| 「取消运行」（返回 `CANCEL_TOO_LATE`） | — | 恢复禁用态；Toast「上传已开始，无法取消」；不改变已完成的阶段 |

| `running` 运行中 | 提交 / 演练开始 | 阶段推进；取消可用（OBS 前） |

| 位置 | 文案 |
|---|---|
| 标题 | `运行中` |

| 回填说明 | `本次使用时间回填：开始时间 = 结束时间 − 时长，服务器记录的时间与实际点击时间不同。` |
| 日志 | `运行日志`；`暂停` / `继续`；空态 `等待运行事件` |
| 取消 | `取消运行`；`正在取消…`；`轨迹上传开始后无法取消` |
| 离开确认 | `确定离开运行页？` / `离开不会停止运行；建议留在本页直到完成。` / `留在本页` / `取消运行并离开` |
| 取消确认 | `确定取消本次运行？` / `取消后不会提交记录。` / `继续运行` / `取消运行` |

#### 验收要点

- 阶段只由事件驱动，不出现定时器假进度。
- 总进度单调递增；乱序事件不会让数字回退。
- OBS 一开始，取消按钮立即禁用；返回 `CANCEL_TOO_LATE` 不改变已有阶段。
- 本地任务在 OBS 前保存；应用被中断后，结果页与「我的」仍能找回任务。
- 演练跳过第 4、5 阶段，不产生服务器记录，不产生待重试任务。
- 回读失败不阻断进入结果页，也不改变成绩有效性。
- 日志脱敏；错误面板不显示 token / 密码 / payload。
- 屏幕保持常亮；离开页面必须确认。
- 360 宽下阶段 + 日志 + 取消按钮同屏可见；更矮屏幕允许滚动，但取消按钮固定。

### 3.5 跑步结果 `/run/result`

#### 目的

回答三个问题：这次到底算不算数；轨迹有没有被服务器正确接收和回读；如果没完成，能不能在本机继续重试。

有效性只能来自服务器回查；回查失败必须显示未知，不能显示成功。轨迹回读是独立维度，回读失败不等于成绩无效。

#### 功能清单

- 查看 Hero 状态：有效、未通过、部分完成、未知、已取消、运行失败、提交未完成、演练完成、演练失败。
- 查看距离、时长、配速三项指标。
- 查看路线与校验：避建筑路线、5 点已接入、无建筑相交、围栏内、距离匹配。
- 查看明细行：签名摘要、OBS 上传、轨迹回读、服务器回查、本地任务。
- 有回查数据时查看有效距离、有效时长、消耗。
- 重新回查。
- 重新回读轨迹。
- 重试提交本地任务。
- 重试演练（演练失败时）。
- 导出记录（真实跑步）。
- 导出轨迹（演练结果）。
- 打开签名摘要 Sheet、OBS 上传 Sheet、轨迹回读 Sheet、服务器回查 Sheet、本地任务 Sheet。
- 返回跑步首页。

#### 入口与出口

| 类型 | 说明 |
|---|---|
| 入口 | 运行成功、失败、取消、回查未知、演练完成、演练失败、重试完成 |
| 出口：返回 | 回 `/`，保留参数与预览；清理上次结果 / 阶段 / 日志；主按钮恢复可用；不自动重新预览 |
| 出口：再次开始 | 无独立按钮；返回跑步首页即可 |
| 页内 | 回查、回读、重试、导出、打开 Sheet 都留在本页 |
| 出口：重试提交 | 进入运行中页展示重试进度；从结果页发起时，完成后回结果页并更新状态；从「我的」发起时，完成后留在「我的」 |

#### 页面结构

1. **Header**：返回 + 标题「跑步结果」。
2. **Hero**：状态图标、标题、副标题。
3. **指标网格**：距离、时长、配速/km；演练结果为轨迹距离、目标时长、平均配速、轨迹点数。
4. **路线与校验区**：路线类型、5 点、建筑、围栏、距离匹配；演练结果同。
5. **明细行**：签名摘要、OBS 上传、轨迹回读、服务器回查；有本地任务时追加本地任务行；有回查数据时追加有效距离、有效时长、消耗。
6. **主按钮**：按状态变化（重新回查 / 重新回读 / 重试提交 / 重试演练 / 导出轨迹）。
7. **文字按钮**：导出记录 / 返回首页。
8. **Sheet**：签名摘要、OBS 上传、轨迹回读、服务器回查、本地任务、重试确认、导出确认。

#### 交互

| 元素 | 操作 | 效果 |
|---|---|---|
| 「重新回查」 | 点击 | 需要 `rrid`；无 `rrid` 时禁用并显示「缺少 rrid，无法回查」；点击后 loading「回查中…」；成功后更新 Hero 与回查行 |
| 「重新回读」 | 点击 | 需要已上传轨迹；点击后 loading「回读中…」；成功后回读行变「已回读」；失败保持成绩有效性，Toast「回读失败，请重试」 |
| 「重试提交」 | 点击 | 有本地任务时可用；打开重试确认 Sheet；确认后进入运行中页展示重试进度 |
| 「重试演练」 | 点击 | 仅在 `dryRunError` 可用；沿用当前距离 / 时长与围栏，重新进入运行中页（演练）；不写服务器 |
| 重试确认 Sheet「重试提交」 | 点击 | 使用同一任务重新提交；成功后回结果页并更新 Hero、回查、回读、本地任务行 |
| 重试确认 Sheet「取消」/ 遮罩 | 点击 | 关闭 Sheet，留在结果页 |
| 「导出记录」 | 点击 | 首次弹出确认 Sheet「导出本次记录？」；确认后导出；成功调系统分享；失败 Toast；导出中 loading |
| 「导出轨迹」 | 点击 | 演练结果可用；弹出确认 Sheet「导出轨迹？」；确认后导出 GeoJSON；成功调系统分享；失败 Toast；导出中 loading |
| 签名摘要行 | 点击 | 打开签名摘要 Sheet：字段数、算法、字段名、掩码值、折叠提示 |
| OBS 上传行 | 点击 | 打开 OBS Sheet：对象键（掩码）、上传状态、字节数、消息 |
| 轨迹回读行 | 点击 | 打开回读 Sheet：回读状态、点数、时间、错误摘要 |
| 服务器回查行 | 点击 | 打开回查 Sheet：rrid、状态、有效距离、有效时长、回查时间 |
| 本地任务行 | 点击 | 打开本地任务 Sheet：任务创建时间、状态、上次错误、重试入口 |
| 返回 | 点击 | 回跑步首页，保留参数与预览；清理上次结果 / 阶段 / 日志；主按钮恢复可用 |
| 回查失败 | 自动 | Hero 保持 / 变为 `unknown`；不得回到 `success`；已有 rrid、里程、签名不被抹掉 |
| 回读失败 | 自动 | 只更新轨迹回读行；Hero 与有效性不变 |

#### 状态

| 状态 | 触发 | 界面表现 |
|---|---|---|
| `success` 有效 | 运行成功且回查明确有效 | Hero 有效；显示 rrid、指标、明细、有效距离 / 时长 / 消耗；轨迹回读行独立显示 |
| `notValid` 未通过 | 运行成功且回查明确无效 | Hero 未通过；有效距离 0.00 km、有效时长 00:00、消耗 — |
| `partial` 部分完成 | 轨迹已上传但结算失败 | Hero「轨迹已上传，结算未完成」；主按钮「重试提交」；有 rrid 时可重新回查 |
| `unknown` 未知 | 回查无结果 | Hero「状态未知」；提示回查未返回结果；不得显示成功 |
| `pendingSubmit` 提交未完成 | 任务已保存在本机，尚未上传轨迹 | Hero「提交未完成」；本地任务行显示「待提交」；主按钮「重试提交」；不显示有效性结论 |
| `cancelled` 已取消 | 运行被取消 | Hero「已取消」；指标为 —；回查 / 重试提交禁用 |
| `error` 运行失败 | 运行失败且无有效 rrid、无本地任务 | Hero「运行失败」；显示失败阶段；回查禁用 |
| `dryRun` 演练完成 | 演练成功结束 | Hero「演练完成」；显示未写入服务器；指标为轨迹统计；校验区全部通过；主按钮「导出轨迹」 |
| `dryRunError` 演练失败 | 演练规划或校验失败 | Hero「演练失败」；显示原因；主按钮「重试演练」；文字按钮「返回跑步」；不显示有效性、rrid、OBS |
| `retrySubmit` 重试确认 | 点「重试提交」 | 重试确认 Sheet |
| `retryProgress` 重试中 | 确认重试后 | 进入运行中页；阶段从本地任务继续；结果页保留 |
| `exportTrack` 导出轨迹确认 | 点「导出轨迹」 | 导出确认 Sheet |
| `exportRecord` 导出记录确认 | 点「导出记录」 | 导出确认 Sheet |
| `signature` 签名摘要 | 点签名行 | 签名摘要 Sheet |
| `obs` OBS 上传 | 点 OBS 行 | OBS Sheet |
| `readback` 轨迹回读 | 点回读行 | 回读 Sheet |
| `recheck` 服务器回查 | 点回查行 | 回查 Sheet |
| `task` 本地任务 | 点本地任务行 | 本地任务 Sheet |

**状态推导顺序（必须严格按此顺序）**

1. 本次为演练：
   - 演练成功 → `dryRun`
   - 演练失败 → `dryRunError`
2. 本次为取消 → `cancelled`。
3. 本地任务状态为「待提交」（尚未上传轨迹）→ `pendingSubmit`。
4. 真实运行失败 / 中断：
   - 已有 rrid 但回查无结果 → `unknown`
   - 轨迹已上传但无有效 rrid → `partial`
   - 本地任务状态为「已上传待结算 / 结算失败」→ `partial`
   - 否则 → `error`
5. 真实运行成功：
   - 服务器回查明确有效 → `success`
   - 服务器回查明确无效 → `notValid`
   - 回查无结果 → `unknown`
6. **轨迹回读状态不参与 Hero 推导。** `success` / `notValid` / `unknown` / `partial` 都可能同时是「已回读 / 未回读 / 回读失败」。
7. 重新回查只更新有效性与回查行；重新回读只更新回读行；重试提交重新推导全部状态。
8. 只有明确的有效 / 无效才显示对应结论；回查无结果一律「未知」。
9. `partial`、`pendingSubmit` 不显示成功对勾；即使轨迹已上传也不代表成绩已结算。

| 上传 / 回读 | `已上传` / `上传失败` / `未上传`；`已回读` / `未回读` / `回读失败` / `回读中…`；`{n} 个点` |
| 本地任务状态 | `待提交` / `已上传待结算` / `结算失败`；`上次错误：{message}` |
| 按钮 | `重新回查` / `回查中…` / `重新回读` / `回读中…` / `重试提交` / `重试中…` / `重试演练` / `导出记录` / `导出轨迹` / `导出中…` |
| 有效数据 | `有效距离`、`有效时长`、`消耗` |
| 未知说明 | `回查未返回结果，暂时无法确认是否有效。` |
| 部分说明 | `轨迹已上传，但结算未完成。请重试提交或重新回查确认。` |
| 未完成说明 | `提交未完成，任务已保存在本机；重试不会重复提交。` |
| 失败说明 | `本次运行未完成，未生成可提交的记录。` |
| 回读说明 | `轨迹回读失败不影响成绩有效性；可重新回读。` |
| 演练说明 | `演练不写入服务器，也不产生成绩记录。` |
| 重试确认 | `重试本次提交？`；`将使用同一任务重新提交，不会重复生成记录；如果服务器已有记录，会恢复原 rrid。`；`重试提交`；`取消` |
| 重试结果 | `重试成功`；`已找到上次记录，已恢复`；`重试失败，请稍后再试` |
| 回读结果 | `轨迹已回读`；`回读失败，请重试` |
| 导出记录确认 | `导出本次记录？`；`导出文件可能包含运行记录，请妥善保管。`；`导出`；`取消` |
| 导出轨迹确认 | `导出轨迹？`；`将导出 GeoJSON 轨迹文件，仅含本次演练的坐标与校验信息，不包含凭证。`；`导出`；`取消` |
| 导出结果 | `记录已导出` / `轨迹已导出`；`导出失败，请重试` |
| 无 rrid | `缺少 rrid，无法回查` |
| 演练失败原因 | `路线规划失败` / `轨迹校验失败` / `目标距离太短` / `打卡点位于建筑内` |

#### 验收要点

- 只有回查明确有效才显示「有效」；明确无效显示「未通过」；回查无结果显示「未知」。
- 回查失败不会把 Hero 改回 success。
- 轨迹已上传但结算失败显示 `partial`；本地任务仍为「待提交」显示 `pendingSubmit`；两者都不是 success。
- **轨迹回读失败不改变 Hero 与成绩有效性。**
- 重试提交使用同一任务，说明不会重复生成记录；恢复已有 rrid 时提示「已找到上次记录，已恢复」。
- 演练结果不显示 rrid、服务器回查、OBS 状态与有效性；不写服务器。
- 演练结果只提供轨迹导出；真实结果提供记录导出；两者导出都需确认。
- 导出内容不含 token、密码、captcha payload、完整设备 ID、盐、完整对象键。
- 所有掩码在 UI 层再执行一次，即使桥接已脱敏。
- 360 宽三列指标不换行、不截断单位。
- 回查、回读、重试、导出失败不抹掉已有结果。

## 4. 跨页流程

### 4.1 冷启动与会话恢复

```text
启动
 └─ 读取本机会话
     ├─ 有会话 → 进入跑步首页
     └─ 无会话 → 进入登录页
```

- 启动画面最长约 1.5s；超时也继续进入登录页。
- 会话读取失败：进入登录页并 Toast「本机会话读取失败」，不阻塞登录。
- 有会话但已失效：冷启动不做网络校验；第一次业务请求返回会话过期后再统一处理。
- 本机待重试任务不因冷启动丢失；有会话时在「我的」显示。

### 4.2 登录与极验

```text
[点击登录]
  → 本地校验非空
  → 检查是否需要安全验证
      ├─ 不需要 → 提交登录
      │     ├─ 成功 → 保存会话 → 清空密码 → 跑步首页 → Toast「登录成功」
      │     └─ 失败 → 错误面板（保留手机号，清空密码）
      └─ 需要
            → 打开安全验证 Sheet
            → 用户拖动滑块
            → 验证成功后提交登录
                ├─ 成功 → 保存会话 → 清空密码 → 跑步首页
                ├─ 验证失败 → 留在 Sheet 重试
                └─ 其他失败 → 关闭 Sheet，回表单错误
```

- 密码只在内存；登录成功 / 失败 / 页面卸载时清空。
- 验证字段任一缺失视为失败，不提交。
- 用户关闭 Sheet：本次验证作废；下次登录重新开始。

### 4.3 规则、围栏与点位

```text
进入规则页
  → 加载规则 + 围栏
  → 默认选中第一个围栏
  → 计分跑 → 查询点位
      ├─ 成功 → 渲染点位与画布
      ├─ 多区域 → 区域选择 Sheet → 重新查询
      └─ 失败 → 点位区块错误面板；不静默使用本地兜底
  → 自由跑 → 不查询点位，显示自由跑说明
```

- 切换模式：清空点位 → 重新加载规则。
- 切换围栏：清空点位 → 自动重查。
- 刷新：规则 / 围栏并行；围栏未变时保留已加载点位。
- 当前围栏与点位会用于首页路线规划。

### 4.4 预览与路线规划

```text
参数合法
  → 等待输入稳定（约 600ms）
  → 路线规划（固定避建筑路线）
      → 成功：渲染围栏 / 建筑 / 道路 / 轨迹 / 点位 / 起终点 / 曲线 / 签名摘要 / 校验摘要
      → 失败：错误面板（路线数据 / 无可走区域 / 点位在建筑内 / 无路 / 距离太短 / 越界 / 穿建筑 / 格式失败）
      → 不回退到直线路线
```

- 首次进入自动规划一次；参数变化后重新防抖规划。
- 规划中：画布 / 图表骨架；主按钮禁用；显示「正在规划避建筑路线…」。
- 规划失败：保留上一份成功预览并标「已过期」；主按钮禁用；错误面板可重试。
- 预览不产生 OBS、结算、回查、回读请求。
- 预览的时间戳是示例；真实提交会重新生成提交内容。

### 4.5 提交与运行

```text
[开始跑步]
  → 参数合法 + 预览就绪 + 参数未过期
  → 确认 Sheet（距离 / 时长 / 配速 / 避建筑路线 + 不可撤销提示）
  → 进入运行中
  → 本机保存任务
  → 阶段推进 → 100%
      ├─ 成功 → 结果页 success / notValid / unknown
      ├─ 部分完成 → 结果页 partial
      ├─ 提交中断 → 结果页 pendingSubmit
      ├─ 取消 → 结果页 cancelled
      └─ 失败 → 结果页 error

[开始演练]
  → 不弹确认 → 运行中（演练）
  → 第 4、5 阶段跳过
  → 结果页 dryRun / dryRunError
```

- 演练不写服务器；完成后进入结果页的演练状态。
- 真实提交会重新生成提交内容，不复用预览结果。
- 页面跳转不等待网络；结果由运行状态持有，结果页读取。
- 本机任务在 OBS 前保存；应用被中断后可在结果页或「我的」找回。

### 4.6 取消与离开

```text
[取消运行]
  → 确认 Sheet
  → 取消请求
      ├─ 成功 → Toast「已取消」→ 结果页 cancelled
      ├─ 太晚 → Toast「上传已开始，无法取消」→ 按钮保持禁用
      └─ 无活动任务 → 回跑步首页
[返回 / 手势离开]
  → 确认 Sheet「确定离开运行页？」
      ├─ 留在本页
      └─ 取消运行并离开 → 同取消流程
```

- OBS 一开始，取消按钮立即禁用，不等接口返回。
- 取消后保留已完成的阶段历史，供结果页和导出使用。
- 取消不删除已保存的本地任务；但取消的本次记录不会被提交，结果页显示 `cancelled`。

### 4.7 结果、回查、回读、重试与导出

```text
进入结果页
  → 读取运行结果 → 按 3.5 的顺序推导 Hero
  → [重新回查] → 回查
      ├─ 成功 → 更新有效性与回查行 → 重算 Hero
      └─ 无结果 → Hero unknown（不得 success）
  → [重新回读] → 回读轨迹
      ├─ 成功 → 回读行「已回读」
      └─ 失败 → 回读行「回读失败」；Hero 与有效性不变
  → [重试提交] → 确认 → 运行中页 → 成功 / 失败
      ├─ 成功 → 回结果页更新状态
      └─ 失败 → 回结果页保留任务，可再次重试
  → [导出记录] → 确认 → 导出 JSON
  → [导出轨迹] → 确认 → 导出 GeoJSON（仅演练）
      ├─ 成功 → 系统分享
      └─ 失败 → Toast
```

- 回查失败只影响「有效性」和回查行，不把已有 rrid / 里程 / 签名抹掉。
- 回读失败只影响「轨迹回读」行，不改变成绩有效性。
- 重试提交使用同一任务；服务器已有记录时恢复原 rrid，不重复生成。
- 导出内容已脱敏，不含 token、密码、完整对象键等敏感值。

### 4.8 待重试任务

```text
「我的」→ 待重试任务行 → Sheet
  → 选择任务 → 重试确认
      → 确认 → 运行中页展示重试进度
          ├─ 成功 → Toast「重试成功」→ 任务移除 → 有 rrid 可「查看结果」
          └─ 失败 → Toast「重试失败，请稍后再试」→ 任务保留
```

- 同一时间只重试一个任务；其余任务点击时提示先完成当前重试。
- 重试需要有效会话；会话过期时先登录，任务保留。
- 清除会话不删除任务；重新登录后继续处理。
- 任务列表按创建时间倒序；状态与结果页共用同一套文案。

### 4.9 会话过期

```text
任意请求返回会话过期
  → 后端发出会话过期事件
  → 前端：停止当前 UI 操作 → Toast「登录已过期」→ 清除会话 → 清空页面状态 → 回登录页
  → 设备 ID、设备档案、待重试任务保留
  → 登录成功后不自动恢复未完成的运行；用户需重新配置
```

- 运行中过期：保留日志到这次会话结束，结果页不显示成功；提示重新登录。
- 登录页显示「登录已过期，请重新登录」的一次性提示。
- 重试中过期：任务保留，回登录页；重新登录后可在「我的」再次重试。

## 6. 待确认与假设

1. **GAP-02（阻塞）**：多区域学校仍无法选择跑步区域；当前 UI 使用已选围栏与点位，若学校有多个区域，路线可能按错误区域规划。需要确认是否增加区域选择器。
2. **Q-05**：目标学校是单区域还是多区域；决定是否必须做区域选择。
3. **Q-04**：真实提交验证使用哪个测试账号；属于协议验证，不阻塞页面逻辑。
4. **避建筑路线的真实可用性**：官方 5 点是否全部落在校园边界内、服务端是否校验轨迹与建筑关系，尚未用真实账号确认。页面逻辑按「规划失败即报错、不回退」处理。
5. **官方点位顺序语义**：当前协议按 `1 = 顺序跑`、其它值尝试全排列处理；UI 不展示顺序，只展示最终路线。若实际语义不同，结果页的「5 点已接入」仍成立，但路线顺序可能变化。
6. **视觉规范已删除**：本次只保留「沿用原控制台风格」的基线说明；重建 UI 规范时需要重新定义颜色、字号、间距、组件尺寸。不得把旧数值当成仍然有效。
7. **实现契约待重写**：`UI实现规格.md` 对应旧 UI v2，已与本文不一致；后续按本文重写接口、桥方法、错误码与脱敏规则。
8. **OpenStreetMap 署名**：路线数据基于 OSM，APK 与 UI 需保留署名与 ODbL 许可说明；本文件已在首页、结果页、免责声明中安排位置。
9. **导出格式**：演练导出轨迹为 GeoJSON；真实结果导出记录为 JSON。若实现阶段改为其他格式，必须先改本文。
10. **重试幂等**：UI 假设重试使用同一任务标识、服务器已有记录时复用原 rrid；若服务端不保证，需在协议侧确认后再保留「不会重复生成」的文案。
11. **清除会话与本地任务**：本文定义为保留待重试任务；若产品希望一并清除，需要修改 3.6 与 4.9。
12. **本轮不做**：历史记录列表、打卡日历、广告、排行榜、多账号、路线编辑、路线来源选择、校园选择、真实地图瓦片、后台常驻服务。

## 7. 维护规则

### 7.1 改页面时按这个顺序

1. **改本文件**：对应页面的功能 / 交互 / 状态 / 文案。行为以本文件为准。
2. **重建视觉规范**：颜色、字号、间距、组件尺寸另立规范；本文件只引用，不复制数值。
3. **重建静态稿**：按本文件逐状态重建；新增 / 删除状态时同步 §5 与静态稿 README。
4. **重写实现契约**：接口、桥方法、错误码、脱敏、GAP 更新 `UI实现规格.md` 与 `AI_SPEC.json`。
5. **跑检查**：静态稿重建后运行静态稿检查；页面逻辑文档检查在静态稿缺席时应只校验页面章节与必需字段。
