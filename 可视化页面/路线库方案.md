# 路线库与人工画线方案

> **状态：已废弃（2026-11-10）— 禁止按本文实现。**
> **废弃原因**：用户已确认改用 OSM 自动路径方案；本方案依赖“人工画线 + 路线库复用”，不满足全自动要求。
> **定位**：仅保留为历史记录；协议侧 / CLI 侧的旧路线复用方案，不属于 UI 规格。
> **新方案**：见 `可视化页面/路线方案/`（待审查后生成）。
> **依据**：2026-11-09 讨论确认的四条判定规则；官方 7.3.92 反编译实现；现有 `协议/7.3.92/` 代码。

---

## 1. 背景与目标

### 1.1 背景

方案 A（人工画路线）如果每轮都重新画，成本过高。官方下发的 5 个必经点是最稳定的路线约束，因此可以用"5 点整体"作为路线是否已经画过的判定条件。

### 1.2 目标

1. **同一组官方 5 点，只人工画一次**；后续直接复用，不再人工画。
2. **每次运行都留一条记录**，可追溯本次用了哪条路线、为什么复用或新画。
3. **复用前必须通过当前围栏/规则校验**，不盲复用。
4. 不改变现有上传链路：`builder` / `sample_route` / `check_track` 的报文格式不变，只替换 `waypoints` 的来源。

### 1.3 非目标

- 不上传地图图片、不上传地图图层；
- 不在协议侧接入高德 SDK 或高德 key；
- 不做服务端路网匹配；
- 不做自动建筑识别（可选扩展，见 §9）。

## 2. 术语

| 术语 | 含义 |
| --- | --- |
| 官方 5 点 | 每次跑步由官方发点接口下发的 `pointsResModels`，作为路线必须经过的硬约束 |
| 路线模板 | 人工画出的 GCJ-02 闭合折线 `[[lng, lat], ...]` |
| 路线库 | 以"5 点整体"为 key，保存路线模板的本地库 |
| 运行记录 | 每次执行的追加式日志，记录当次点位、路线、参数、结果 |
| 复用 | 同 key 命中且通过校验后，直接使用已保存的路线 |
| 新画 | 未命中或校验不通过时，人工画一条新路线并入库 |

## 3. 官方点位机制（事实）

以下事实来自官方 7.3.92 反编译与现有协议代码，决定了路线库的 key 设计。

### 3.1 每次跑步重新下发 5 点

```http
POST /api/v560/get/1/distance/{distance}
body: {
  longitude, latitude,        // 当前 GCJ 位置（gLng/gLat）
  selectedUnid, uuid, runec, runAreaId, sign
}
→ { pointsResModels: FivePoint[5], sportStartTime }
```

- 代码位置：`协议/7.3.92/policy/client.py:90-119,157-184`；
- 客户端每次生成新的 `uuid`，并把同一个 `uuid` 复用给成绩上报；
- 服务端只返回本轮 5 个点，**不返回完整点位池**。

### 3.2 点位来自学校配置的固定池

- `FivePoint` 有 `isFixed`（必经/普通）、`position`、`pointName`；
- 官方客户端存在按学校维度配置的点位实体 `RunPoint`（`pid` / `unid` / `runMode` / `serialNum` / `isFixed` / 有效期）；
- 所以坐标不是任意随机经纬度，而是学校点位池中的真实地标。

### 3.3 三种跑步模式

| 模式 | 官方类 | 行为 |
| --- | --- | --- |
| 随机跑 | `RunRandomStartViewModel` | 服务端下发普通点 + 必经点，直接使用 |
| 顺序跑 | `RunSequenceStartViewModel` | 客户端对 5 点做全排列（120 种），按学校距离带筛选，中间带随机选一种，并重设 `position` |
| 终点跑 | `RunEndStartViewModel` | 调 `/api/v560/get/destinationRun/points`，只使用终点 |

### 3.4 结论

- 5 点会随每轮下发变化，**不能把某一次的 5 点硬编码进模板**；
- 5 点的**集合**比顺序更稳定，适合作为路线复用的主判据；
- 围栏与规则会独立变化，不能因为"5 点相同"就跳过合规校验。

## 4. 方案 A 原理

### 4.1 不是把路线画到官方地图上

官方地图没有"接收路径图片"的接口。官方 App 的详情页做的是：

```text
get_one_record
  → jsonFromObs == 1 时下载 OBS run_data
  → 解析 LocJsonEntity → List<MyLocation>
  → 转 SWLatLng(gLat, gLng, lat, lng)
  → 高德 PolylineOptions().addAll(点列表)
```

所以：

- 我们上传的是**坐标数组**；
- 官方 App 用高德 SDK **自己画线**；
- 人工画的路线只是"坐标模板"，不是地图图层。

### 4.2 为什么要人工画

当前 `builder.py` 只把 5 个官方点用直线连接成多边形（`running/builder.py:124-126`），不读路网、不避建筑。人工画路线的目的是：

- 让轨迹沿操场/校内道路走；
- 避开建筑；
- 让官方地图上的形状看起来像真实跑步。

### 4.3 人工画线的粒度

- 只画**拐点/关键点**，不需要每米一个点；
- 一条普通校园环线通常 **8–30 个拐点**；
- 最终上传的 GPS 点由 `sample_route` 每 3 秒插值生成（3000m / 1060s 约 354 个点）。

## 5. 手动画线操作

### 5.1 输入

| 数据 | 来源 | 坐标 |
| --- | --- | --- |
| 学校围栏多边形 | `getGeoFenceForRun` | `glat/glon`（GCJ-02） |
| 官方 5 个必经点 | `v560` 发点接口 | `glat/glon`（GCJ-02） |
| 学校规则 | `runModePolicy` | 最低里程/时长、配速、步频、有效时段 |

### 5.2 输出

```json
{
  "frame": "GCJ-02",
  "unid": 123401,
  "areaId": 8,
  "loop": [
    [120.000100, 30.000100],
    [120.000900, 30.000100],
    [120.000900, 30.000600],
    [120.000100, 30.000600],
    [120.000100, 30.000100]
  ]
}
```

- 坐标顺序：`[经度 lng, 纬度 lat]`；
- 坐标系：GCJ-02；
- 必须是闭合环；
- 必须经过 5 个必经点（或在运行时由拼接器插入）。

### 5.3 工具选择

| 工具 | 需要 key | 输出坐标系 | 适用 |
| --- | --- | --- | --- |
| 高德网页坐标拾取器 | 通常不需要 | GCJ-02 | 单校区、拐点少、最省事 |
| QGIS | 不需要 | WGS84（需转 GCJ） | 多校区、要导入围栏/建筑 |
| 高德 JS API 小页面 | 需要 | GCJ-02 | 经常画、鼠标拖拽导出 |
| 本地 HTML 路线编辑器 | 不需要 | 自定义 | 专用工具（后续可选） |

### 5.4 推荐操作步骤（高德拾取器）

1. 导出围栏 + 5 点（建议新增只读命令 `--dump-geo`）；
2. 打开高德坐标拾取器，搜索学校或粘贴围栏首点定位；
3. 切换到卫星图，确认底图与围栏一致；
4. 从 5 点之一出发，沿操场/道路依次点拐点，记录 `lng, lat`；
5. 回到起点，闭合；
6. 保存为 §5.2 的 JSON；
7. 跑本地校验（§7.4），通过后入库。

### 5.5 备选：真实走一遍导出 GPX

如果不想在地图上逐点点：

```text
手机轨迹 App 走/跑一次 → 导出 GPX（WGS84）
→ 转 GCJ-02 → 抽稀（Douglas-Peucker，保留 20–50 点）
→ 作为路线模板
```

优点：沿真实道路、天然避开建筑；缺点：需要实地走一次。

### 5.6 画线规则

1. 坐标是 `[lng, lat]`，不是 `[lat, lng]`；
2. 用 GCJ-02，不用 WGS84；
3. 必须闭合；
4. 必须经过 5 个必经点（0.1m 内，或由拼接器插入）；
5. 全程在围栏内；
6. 拐弯处多加点，直道少点；
7. 路线周长 ≤ 目标距离，否则 `sample_route` 会拒绝。

## 6. 路线库设计

### 6.1 两个实体

#### RouteEntry（路线库条目）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `route_id` | string | 路线唯一 ID |
| `unid` | int | 学校命名空间 |
| `point_set` | JSON | 当次 5 点（原始 + 归一化） |
| `key` | string | 归一化 5 点集合的 hash |
| `route` | JSON | GCJ-02 闭合折线 |
| `route_length_m` | float | 路线周长 |
| `source` | string | `manual` / `auto` |
| `fence_hash` | string | 创建/最近校验时的围栏 hash |
| `rule_hash` | string | 创建/最近校验时的规则 hash |
| `status` | string | `valid` / `needs_review` / `invalid` |
| `created_at` | datetime | 创建时间 |
| `last_used_at` | datetime | 最近使用时间 |
| `last_verified_at` | datetime | 最近校验通过时间 |
| `notes` | string | 人工备注 |

#### RunRecord（运行记录，追加式）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `run_id` | string | 本次运行 ID |
| `timestamp` | datetime | 运行时间 |
| `uid` / `unid` / `runAreaId` | int | 账号与区域 |
| `policy` / `sequenceStrength` | int | 跑步模式 |
| `raw_points` | JSON | 官方下发的 5 点（原样） |
| `normalized_key` | string | 归一化后的 key |
| `route_id` | string | 复用的路线 ID（新画则为新 ID） |
| `target_distance` / `target_time` | int | 本次目标 |
| `route_length_m` | float | 实际路线长度 |
| `validation` | JSON | 围栏/点位/距离/规则校验结果 |
| `result` | JSON | 成功/失败、rrid、是否达标 |

### 6.2 Key 定义（落实四条规则）

```text
归一化：
  每个点保留 6 位小数
  允许浮点误差：默认 EPS = 5 米（可配置）
  顺序无关：对 5 个点做集合匹配，不看顺序

key = sha1(unid + "|" + 排序后的归一化 5 点)
```

| 规则 | 处理 |
| --- | --- |
| ① 允许浮点误差 | 点匹配用 `EPS=5m`，不要求坐标完全相等 |
| ② 顺序不同算同一条 | key 对点做集合归一化，顺序不参与 hash |
| ③ 距离/时长不同算同一条 | 目标距离/时长不进 key，只作为 RunRecord 的运行参数 |
| ④ 围栏/规则变化必须符合 | key 不含围栏/规则，但 RouteEntry 保存 `fence_hash`/`rule_hash`；复用前强制重新校验 |

> 说明：`unid` 作为命名空间加入 key，避免两所学校点位重合导致误命中；5 点仍是主判据。

### 6.3 复用流程

```text
① 拉取围栏 + 规则 + 当次 5 点
        ↓
② 归一化 → 算 key
        ↓
③ 查 RouteEntry
   ├─ 命中
   │    → 复用前校验（§6.4）
   │       ├─ 通过 → 复用，更新 last_verified_at
   │       └─ 不通过 → 标记 needs_review/invalid，转未命中
   └─ 未命中
        → 导出 GeoJSON（围栏 + 5 点）
        → 人工画一次
        → 导入 + 校验
        → 新建 RouteEntry
        → 使用
        ↓
④ 生成轨迹并上传
        ↓
⑤ 追加 RunRecord
```

### 6.4 复用前校验

| 校验 | 规则 | 不通过处理 |
| --- | --- | --- |
| 5 点都在路线上 | 每个点距折线 ≤ 0.1m；否则运行时插入 | 不能复用 |
| 路线在围栏内 | 所有顶点/采样点在围栏内，线段不穿出围栏 | 标记 `invalid` |
| 目标距离 ≥ 路线长度 | 否则 `sample_route` 报 `target distance is too short` | 换短变体或调整目标 |
| 规则合规 | 最低里程/时长、配速、步频、有效时段、单日额度 | 调整运行参数，或标记需复核 |
| 围栏/规则版本 | `fence_hash` / `rule_hash` 变化 | 强制重新校验，不静默复用 |

**原则：命中 ≠ 可用。命中只是找到候选路线，过完校验才算复用。**

### 6.5 顺序与距离

#### 顺序不同（规则②）

- 路线存为**无向闭合环**；
- 运行时根据当次点顺序选择起点（旋转）和方向（正/反）；
- 顺序跑模式下，确保 `position` 与实际经过顺序一致。

#### 距离/时长不同（规则③）

- 同一 key 复用同一条路线；
- 目标距离 ≥ 路线长度 → `sample_route` 自动绕圈凑够；
- 目标距离 < 路线长度 → 物理上不够短：
  - 优先使用同一 key 下的**长度变体**（短/中/长）；
  - 没有合适变体 → 提示人工补一条更短的，或调整目标距离。

### 6.6 围栏/规则变更

- `fence_hash`：围栏多边形归一化后的 hash；
- `rule_hash`：`minDistance`、`minRunTime`、`speedTop/Bottom`、`stepTop/Bottom`、`policy`、`sequenceStrength`、`validTime`、`runAreaModels` 的 hash；
- 任一变化 → 复用前重新校验；
- 几何不合规（越界/漏点）→ `invalid`；
- 仅规则参数变化（配速/步频/时长）→ 调整运行参数，路线可继续用。

### 6.7 存储

建议 SQLite（Python 标准库自带，未来 Chaquopy 可用）：

```text
数据/路线库/routes.sqlite3
  ├─ routes          (RouteEntry)
  ├─ route_points    (路线顶点，按顺序)
  ├─ route_variants  (同 key 的多长度变体，可选)
  └─ run_records     (RunRecord)
```

- 数据目录默认 `.gitignore`，避免把学校真实坐标提交进仓库；
- 若先做 MVP，可用 JSON 文件，但记录多了以后迁移 SQLite。

### 6.8 数据格式

#### 导出给画图工具

```json
{
  "frame": "GCJ-02",
  "unid": 123401,
  "areaId": 8,
  "fence": [[120.000000, 30.000000], [120.001000, 30.000000]],
  "checkpoints": [
    {"lng": 120.000100, "lat": 30.000100, "gLng": 120.000100, "gLat": 30.000100,
     "name": "P1", "isFixed": 1, "position": 1}
```

## 8. 分阶段实施

| 阶段 | 内容 | 交付 |
| --- | --- | --- |
| P1 | 数据模型 + 只读导出 + 人工导入 + 校验器 | 能画出第一条路线并入库 |
| P2 | 运行时查库 + 复用 + 运行记录 | 同 5 点不再提示画图 |
| P3 | 命中率统计 + 多长度变体 + 可选自动路由 | 降低人工介入频率 |

### P1 具体交付

- `--dump-geo`：只读导出围栏 + 5 点为 GeoJSON；
- `check_route.py`：校验路线（5 点、围栏、长度、闭合）；
- `route import`：把人工画的 JSON 写入路线库；
- SQLite 表结构与初始化。

### P2 具体交付

- `route lookup`：按 5 点 key 查询；
- 复用前校验；
- `RunRecord` 追加；
- 与 `execute_full_run` 集成。

### P3 具体交付

- 命中率统计；
- 同 key 多长度变体；
- 可选：路线图自动路由（人工只在失败时介入）。

## 9. 验收标准

1. 同一组 5 点（误差 ≤ 5m、顺序任意）→ 不再提示人工画，直接复用。
2. 5 点有一处不同 → 新增一条 `RouteEntry`，提示人工画一次。
3. 5 点相同、目标距离/时长不同 → 仍复用同一条目，不新增。
4. 5 点相同、但围栏/规则变化 → 强制重新校验；不合规则标记 `invalid`，不得静默使用。
5. 每次运行都有一条 `RunRecord`。
6. 复用后的轨迹通过 `check_track`：距离、时间戳、5 点全部通过。
7. 上传报文格式与现有版本一致，服务端回查 `status=0`（真实账号验证）。

## 10. 风险与待确认

| 风险/问题 | 说明 | 建议 |
| --- | --- | --- |
| 官方 5 点重复率未知 | 若每轮都随机，路线库命中率低 | 先测量 20–30 次发点结果的唯一集合数 |
| 浮点误差阈值 | 太小会假未命中，太大会误命中 | 默认 `EPS=5m`，可配置 |
| 目标距离 < 路线长度 | key 忽略距离，但路线有物理长度 | 同 key 多长度变体；否则提示重画 |
| 顺序跑模式 | 顺序不同算同一路线，但 `position` 可能不同 | 存无向环，运行时旋转/反向 |
| 围栏/规则变更 | 旧路线可能失效 | 保存 hash，复用前强制校验 |
| 坐标帧 | WGS84/GCJ/百度混用会偏移 | 统一 GCJ-02，用官方 5 点做控制点 |
| 数据隐私 | 学校坐标不宜公开 | 数据目录默认不提交仓库 |
| 手工成本 | 每条新 5 点组合要画一次 | 路线库摊销；可选 GPX/自动路由 |
