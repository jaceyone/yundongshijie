# 手动路线与路线库方案

> **状态**：路线库/校验/采集/编辑器/自动展开/自动修复已实现（2026-11-13）；官方侧 `route_provider` 钩子已于 2026-11-13 接入，手动画线改为「开始跑步并取到当天点位后」进行，保存后自动继续提交；路线库管理页（分组列表 + 编辑已有条目）已于 2026-11-14 实现。
> **定位**：第二路线源，只在 `电脑一键启动` 桌面工具落地；`协议/7.3.92/` 的提交链路由用户维护，本方案只给它一个可选钩子。
> **关系**：OSM 自动路线仍是默认/回退（`OSM自动轨迹生成与上传方案.md`）；本文替代已废弃的 `可视化页面/路线库方案.md` 中「闭合环 + `[lng, lat]`」的旧设计。取点锚点与未命中的三选一流程见 `锚点就近取点方案.md`（已实现，桌面端）。
> **已确认**：provider 回调；开放折线不要求闭环；路线顺序由手画路径决定；**AMap 官方瓦片底图（标准/卫星）**；路线短于目标时沿原路折返并校验折返段；同点位多长度变体自动选。
> **原型**：`电脑一键启动/route_library.py`、`电脑一键启动/route_sampler.py`。

## 0. 结论摘要

- 手画路线是**开放折线** `[[lat, lon], ...]`（GCJ-02），不要求首尾闭合。
- 协议条件：**路线长度 ≤ 目标距离**。路线短于目标时，桌面端先按原路反向折返展开到目标距离，再把「长度 = 目标」的折线交给协议；不生成手画折线之外的坐标（2026-11-16 起，见《手动路线折返展开方案》）。
- 5 个官方打卡点必须是路线上的**精确顶点**（默认 0.1 m），否则 `check_track` 报错。
- 路线库按 **5 点集合**匹配（`unid + area_id` 命名空间、顺序无关、EPS 5 m）；同一点位集可存多条不同长度路线。
- 官方侧新增 `route_provider` 回调：取点后、排序/规划前调用，返回 `(polyline, ordered_checkpoints)`；手动模式跳过 `select_official_order`。
- 编辑器在 `电脑一键启动` 内用 Tkinter Canvas + **AMap 官方瓦片**（标准/卫星），GCJ-02；瓦片缓存到本地，无 key/SDK。
- 不静默回退 OSM：命中失败或几何不合法时，提示用户「继续画 / 画新路线 / 改用 OSM / 取消」。

## 1. 背景与目标

### 1.1 背景

- 2026-11-13 起计分跑固定 OSM；用户要求增加第二路线源「手动画路线 + 路线库」。
- 当前 `execute_full_run` 在提交链路内部取围栏、5 点和 `run_uuid`（`running/client.py:332-333`），脚本在开跑前拿不到当次点位，无法按点位查库。
- 旧 `路线库方案.md` 要求闭合环、使用 `[lng, lat]`，与当前协议 `route_polyline` 的 `[lat, lon]` 相反，不能直接复用。

### 1.2 目标

1. 用户可以在桌面地图上画一条经过 5 个官方点的路线。
2. 同一点位集再次出现时，优先复用上次画的路线；距离不合适时在同点位下换一条长度合适的变体。
3. 每条画过的路线都有记录，可追溯、可删除、可重新校验。
4. 不修改官方提交链路的业务逻辑，只加一个测试缝。
5. 底图与官方 App 一致：使用 AMap 官方瓦片（标准/卫星），可缓存；打包校园数据只做校验和离线兜底。

### 1.3 非目标

- 不做自动画线（OSM 已负责）；手动模式只做人工绘制。
- 不做服务端同步、多账号共享。
- 不把路线库上传到任何服务器。
- 不改变官方上报字段、OBS 结构、结算流程。
- 不接高德 JS SDK/key；底图只用 AMap 瓦片，不调用官方业务 API。

## 2. 事实与约束

### 2.1 协议坐标与格式

- `route_polyline` 是 GCJ-02 的 `[lat, lon]` 序列（`running/builder.py:150-157`）。
- 官方 5 点同时有 `lat/lng`（BD-09）与 `glat/glon`（GCJ-02）；路线、排序、地图都用 GCJ，`fivePointJson` 保留原值。
- 路线库、编辑器、GeoJSON 统一使用 `[lat, lon]`；不再使用旧文档的 `[lng, lat]`。

### 2.2 `sample_route` 的距离语义

`running/consistency.py:54-99`：

- 折线长度 `L = Σ distance(v_i, v_{i+1})`。
- `require_all=True` 时要求 `目标距离 + 0.001 ≥ L`；否则报 `target distance is too short`。
- 协议本身仍把折线当闭环：目标大于 `L` 时，`sample_route` 会从最后一个顶点**直线**回到第一个顶点继续走。
- **手动路线不会把短于目标的折线交给协议**：provider 先按原路反向折返展开到目标距离，协议看到的 `L = 目标`；整秒采样补偿多走的几米沿原路继续（2026-11-16 协议新增折返分支），不再产生终点→起点直线。
- 目标距离等于 `L` 时，单程结束，不使用补偿段。

因此（手动路线）：

| 目标距离 | 手画路线长度 | 交给协议的折线 | 结果 |
| --- | --- | --- | --- |
| 3000 m | 3000 m | 3000 m 单程 | 单程，A→B→C |
| 3000 m | 1450 m | 1450 m + 1550 m 原路折返 | 正向 1 趟 + 反向 1.07 趟，无新坐标 |
| 3000 m | 3200 m | 截断到 3000 m | 截断后仍覆盖 5 点则可用，否则打开编辑器重画 |

### 2.3 打卡点精度

- `check_track` 要求每个官方点距某个采样点 ≤ 0.1 m（`running/consistency.py:112-118`）。
- `sample_route` 只把折线顶点保留为采样点；因此官方点必须作为**顶点**插入折线，不能只“画在旁边”。
- 编辑器保存时自动把 5 点坐标插入为精确顶点；连接线要校验不穿建筑。

### 2.4 建筑与围栏

- 校园数据 `running/data/campus_xuchang_280173698.json` 的 `boundary` 是「官方围栏 + 350 m」；官方 5 点中有 4 个在官方围栏外，因此不能只按官方围栏校验。
- 真实 P3 落在 OSM 建筑 `280782570`（静庐8）内；OSM 规划器会打通 2 m 接入通道并放行该建筑。手动路线也必须允许「包含打卡点的建筑」，否则 `validate_track` 直接失败。
- 手动校验复用 `TrackPlanner.validate_track`（`running/osm/planner.py:576`），并额外警告：连续处于允许建筑内超过 30 m 时提示接入通道过长。

### 2.5 官方顺序

- `select_official_order` 在距离窗口内随机选一个 5 点排列（`running/route_order.py:72-120`）。
- 手动模式由手画路径的经过顺序决定 `position`；官方侧应跳过 `select_official_order`，使用 provider 返回的 `ordered_checkpoints`。
- 如果后续发现服务端不接受客户端自定义顺序，退回「只复用循环同构的顺序」策略（见 §11）。

## 3. 路线格式与校验

### 3.1 格式

```json
{
  "frame": "GCJ-02",
  "is_closed": false,
  "polyline": [[34.040000, 113.860000], [34.040500, 113.860000], [34.040500, 113.860500]],
  "length_m": 1450.7,
  "order": [0, 2, 1, 3, 4]
}
```

- 至少 2 个顶点；开放折线，首尾不要求相同。
- `order` 是 5 个打卡点在路线上的经过顺序（下标指向保存的 `points` 列表）。
- 首尾相同也允许，但不会因此获得额外行为；`is_closed` 仅作展示。

### 3.2 校验规则

| 校验 | 规则 | 失败处理 |
| --- | --- | --- |
| 顶点 | ≥ 2 个，坐标有限，**禁止**连续重复顶点 | 阻止保存 |
| 长度 | `0 < L ≤ 目标距离 + 0.001` | 阻止保存，提示超出多少米 |
| 目标范围 | `目标 ≥ min_distance`（当前 1000 m）；允许超过 `day_goal` / 3000 m | 低于最低里程时阻止；超过 3000 m 不再阻止 |
| 趟数 | `目标距离 / L ≤ 8` | 警告；自动选库时过滤 |
| 打卡点 | 每个官方点距最近顶点 ≤ 0.1 m | 阻止保存，提示插入精确点 |
| 顺序 | 每个打卡点只出现一次；同顶点歧义给警告 | 警告 |
| 建筑 | `validate_track` 0 穿建筑（打卡点所在建筑除外） | 阻止保存 |
| 围栏 | 所有采样点在允许边界内 | 阻止保存 |
| 折返段 | 当 `L < 目标` 时，原路反向折返段也纳入 `validate_track`，与提交几何同源 | 阻止保存 |
| 接入通道 | 在允许建筑内连续行走 > 30 m | 警告 |

**自动修复**：校验/保存前先调用 `auto_repair()`：

1. 目标范围越界：阻止并提示修改 `config.json`（运行目标不自动改）；
2. 过近重复顶点：移除；与上一保留顶点间距 <3 m 的过密顶点也移除（打卡点与首尾保留）；
3. 路线长于目标：截断到目标；
4. 缺打卡点：≤30 m 直接插入；更远用 A* 绕到打卡点再回到原段；
5. 穿建筑/越界/不可走段：不再自动绕行，直接提示「第 N 段穿建筑/边界，请重画」；
6. 修复后重新校验；只有无法修复（穿建筑/边界、缺 2 点、目标越界）才提示错误。

实现：`电脑一键启动/route_library.py` 的 `validate_route()`；`traversal_points()` 与 `expand_polyline_to_distance()` 同源，校验几何 = 提交几何。

## 4. 路线库

### 4.1 数据模型

```text
RouteEntry
  route_id            单条路线 ID
  group_id            同一点位集的分组 ID
  points_key          点位集索引 key
  unid / area_id      命名空间
  campus              校园数据 id
  points              5 个官方点（保留 lat/lng 与 glat/glon）
  order               经过顺序（下标）
  polyline            [[lat, lon], ...]（GCJ-02）
  length_m
  is_closed           false
  status              valid / needs_review / invalid
  source              manual
  notes
  created_at / last_used_at / last_validated_at
  validation          最近一次校验报告
  schema_version
```

路线库文件：`电脑一键启动/route_library.json`（已 gitignore）。
运行历史：`电脑一键启动/route_history.jsonl`（追加式，记录 add / use / miss）。

### 4.2 点位 key 与匹配

- key = `sha1(unid | area_id | 排序后的量化点位)`，量化 5 位小数（约 1 m）。
- key 只作索引/去重；实际匹配用 **EPS 5 m 的双向最近点匹配**，顺序无关。
- `unid` 与 `area_id` 是命名空间；避免不同学校/区域误命中。
- 目标距离、时长、顺序**不进入 key**，只存在条目里。
- 双人/多点匹配用全排列（5 点 120 种）；点数多时退化为贪心。

### 4.3 变体与选择

同一点位集允许多条不同长度的路线（变体）。**命中判定（2026-11-14 起）**：

1. 命名空间匹配（`unid` / `area_id`；任一未知时不比较）。
2. 点位集在 EPS 5 m 内匹配，顺序无关。
3. 能把当次 5 点坐标 rebase 进旧折线的对应顶点。

不再要求 `status=valid`、长度 ≤ 目标、趟数 ≤ 8、重新校验通过——这些只作为确认框里的提示，或留给协议提交前的校验。

命中后按以下顺序选变体：

1. 长度 ≤ 目标的变体优先；
2. 其次趟数少；
3. 再按 5 点最大偏差小、最近使用、最近创建。

路线长于目标时：

- 截断到目标后仍覆盖全部 5 点 → 确认框提示「将截断」，可直接使用；
- 截断后会缺少打卡点 → 提示命中但无法直接使用，打开编辑器重画。

示例（同一点位集，长度过滤只影响“优先选谁”，不再阻止命中）：

| 变体 | 目标 1000 m | 目标 1500 m | 目标 3000 m |
| --- | --- | --- | --- |
| 980 m | 选中（1.02 趟） | 优先选中（1.53 趟） | 优先选中（3.06 趟） |
| 1450 m | 命中但超长（提示截断/重画） | 选中（1.03 趟） | 选中（2.07 趟） |
| 2210 m | 命中但超长（提示截断/重画） | 命中但超长（提示截断/重画） | 选中（1.36 趟） |

没有命中时：未命中才打开编辑器新建；**不静默切 OSM**。

`find()` 保留严格模式（状态/长度/趟数/复核全过），供自检与需要严格筛选的调用；跑步链路使用 `find_by_points()`。

### 4.4 复用前 rebase

同一点位集再次下发时，坐标可能有几米抖动（仍在 EPS 5 m 内）。不能直接返回旧折线，否则 `check_track` 的 0.1 m 精度会失败。命中路径会：

1. 用 `vertex_indices` 找到每条库路线中 5 个打卡点对应的折线顶点；
2. 把**当次** 5 点坐标替换进这些顶点，得到 `adjusted_polyline`；
3. 宽松命中不再重新执行 `validate_route`（建筑/边界/折返段由协议提交前复核）；严格模式 `find()` 仍会；
4. provider 返回 `adjusted_polyline` 和按路径顺序排列的 `ordered_checkpoints`。

如果两个打卡点映射到同一个顶点，或缺少顶点映射，该条目跳过，不做静默放宽。

### 4.5 历史记录

`route_history.jsonl` 每次追加一行：

```json
{"event":"use","route_id":"...","points_key":"...","length_m":1450.7,"target_distance_m":3000,"timestamp":"2026-11-13T16:00:00"}
```

用途：统计命中率、排查“为什么没用上次那条”、复现某次选择。

## 6. `电脑一键启动` 集成

### 6.1 配置

`config.json` 新增：

```json
"route_mode": "osm",
"route_library": "route_library.json"
```

- `route_mode`: `osm`（默认）/ `manual`。
- `manual` 下 provider 返回 `None` 时直接失败，不回退 OSM；UI 在路线库未命中时提供显式「OSM 自动规划」（`RouteDecision.osm()`）。

### 6.2 主窗口

- 路线来源单选：`OSM 自动` / `手动路线库`。
- 主窗口**不再提供独立的「画路线」按钮**；手动画线只能发生在本次运行取到当天官方点位之后。
- 编辑器目标距离**只读**，来自 `config.json` / provider context；只要求不低于 `min_distance`，允许超过 `day_goal` / 3000 m。画线/保存会按目标距离原路折返展开，不能在编辑器里改大。
- 新增「取点位置」行：显示当前锚点池摘要，右侧按钮打开锚点编辑器（见 `锚点就近取点方案.md` §7）。
- 手动模式下点「开始跑步」后：
  - 登录前随机选 1 个取点锚点，显示在确认框里；点「否」不登录、不取点。
  - 先登录并取**当天**官方 5 点（协议侧 `get_checkpoints_for_run(anchor_gcj=...)`）。
  - 命中（只按 5 点位置）→ 确认框：路线长度、趟数/折返距离/截断提示、状态、最大点偏差、最近使用；「是」使用 /「否」重画。
  - 路线长于目标且截断后缺打卡点 → 提示命中但无法直接使用，直接打开编辑器。
  - 未命中 → 三选一：**手动画线 / OSM 自动规划 / 取消**；三者复用同一次取点结果，不重新请求五点接口。
  - 画完保存 → provider 返回展开后的折线，协议继续生成轨迹/OBS/提交。
- 日志写清：`本次取点锚点: ...`、`路线选择: 已取得当天官方点位 ...`、`路线库: 命中 route_id=...`、`路线决策: 路线库未命中 → 用户选择 ...`。
- 「路线来源」行右侧有「管理路线库」按钮，打开路线库管理页（见 §5.3）；运行中禁止打开，避免与 provider 同时读写路线库。
- 命令行 `python route_editor.py --latest-sampler` 仍可离线预览/存库，但不参与本次提交。

### 6.3 演练

- 建议新增「路线演练」：调用 `execute_full_run(dry_run=True, route_provider=...)`，取点、选/画路线、生成并校验轨迹，但不写 OBS、不提交。
- 这比现有的「只登录」演练更接近真实链路，用于验证官方实现。

### 6.4 线程

- provider 在 `runner.run()` 的 worker 线程里被调用。
- 不能从 worker 直接碰 Tk；通过 `queue` 把 `RouteContext` 交给主线程，主线程打开编辑器/确认面板，worker 用 `threading.Event` 等待。
- 用户关闭窗口/取消时返回 `RouteDecision.cancel()`（或旧行为 `None`），本次不提交；未命中三选一的三条路径都复用同一次取点结果。
- 禁止在 worker 里 `root.after()` 或直接操作控件。

## 8. 点位采集

### 8.1 目的

路线库的命中率取决于「同一组 5 点」出现的频率。先测量，再决定 EPS、变体数量和是否值得投入编辑器。

### 8.2 工具

```bash
cd 电脑一键启动
python route_sampler.py --runs 3 --yes
```

- 一次登录，连续取 N 次点（默认 3 次、间隔 3 秒）。
- 官方 5 点接口 **5 分钟内最多取 3 次**（`10603`）；默认遇到限流就停止。需要更多样本时加 `--wait-limit`，程序会等 300 秒再继续。
- 只读接口：取规则、围栏、5 点；不生成轨迹、不提交。
- 输出：唯一集合数、重复命中率、同一集合的点位抖动（最大/平均）、不同集合的最小点距、顺序变化种类。
- 报告写到 `电脑一键启动/logs/points-*.json`（已 gitignore）。

### 8.3 首次实测（2026-11-13）

- 同一账号连续 3 次取点（第 4 次起返回 `10603`）：**3 次同一组 5 点，key 完全相同，坐标抖动 0.00 m，顺序 1 种**。
- 5 点全部在允许边界内且可走，不在建筑内；自然顺序直线长度 505.3 m，但 P1→P2 段穿过建筑 `280771265`（宁园4），说明手画路线必须绕行，校验器能正确拦截。
- 结论：点位集高度稳定，路线库命中率前景好；但取点有 5 分钟 3 次上限，**provider 回调必须在同一次取点后完成画线，不能先预取再提交**。

### 8.4 判读

- 同一集合命中率高、抖动 ≤ 5 m → 路线库可行，EPS 5 m 合理。
- 抖动 > 5 m → 提高 EPS 或改用“最近 5 点”匹配；同时记录路线库失效风险。
- 唯一集合数接近取点次数 → 路线库命中率低；需要更多变体或考虑以「点位池 + 最近邻」代替精确集合。
- 官方顺序变化多 → 手动模式必须由路径决定 `position`，或只在顺序兼容时复用。

## 10. 验收

1. 同一组 5 点（EPS 5 m、顺序任意）第二次出现时，自动命中上次路线。
2. 目标距离 3000 m、路线 3000 m → 单程轨迹，5 点全部经过。
3. 目标距离 3000 m、路线 1450 m → 轨迹为原路折返（正向 1 趟 + 反向 1.07 趟），不含手画折线之外的坐标，折返段不穿建筑。
4. 目标距离 1000 m、路线 1450 m → 保存/提交前明确失败，提示路线过长。
5. 路线穿过建筑 → 保存被阻止；手动点画在建筑内（官方 P3）→ 仅允许该建筑的短接入。
6. 路线库 JSON 可读、可删除、可重新校验；历史记录有 add/use/miss。
7. 真实 dry-run 可导出 GeoJSON，轨迹与 5 点重合。
8. 一次受控真实提交后，官方 App 详情页轨迹与 5 点重合，`status=0`。
9. 目标 5000 m：编辑器允许保存并展开到 5000 m；`config.json` 的 `distance=5000` 时 runner 与协议都不再按 3000 m 拒绝，服务端是否接受需一次受控提交确认。
10. 模板 962 m + 目标 3000 m → 沿原路折返展开为 3000 m（约 3.12 趟），轨迹只含模板折线坐标。
11. 路线缺一个 89 m 外的打卡点 → 自动 A* 绕到点并回到原段，校验通过。
12. 手动模式点「开始跑步」→ 登录 → 取当天官方点位 → 才打开编辑器；保存后自动继续生成轨迹/OBS/提交，不读取 `logs/points-*.json` 旧快照。
13. provider 返回 None / 折线超长 / 点位顺序不匹配 → 分别报 `manual_route_missing`、`manual_route_too_short`、`manual_route_checkpoint_mismatch`，不进入上传。
14. 主窗口点「管理路线库」→ 按点位组分组列出变体；双击变体进入编辑器，保存后原条目的长度/顺序/备注更新，条目数不变（不新增变体）；删除后列表与 JSON 同步。历史记录出现 `update` / `notes` / `delete` 事件。

## 11. 风险与待确认

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 服务端是否接受客户端自定义 `position` 顺序 | 轨迹与顺序不一致，可能判无效 | 先 dry-run；必要时退回“只复用顺序兼容的路线” |
| 同一组 5 点重复率低 | 路线库命中率低，人工成本高 | 先跑 `route_sampler` 测量；必要时改点位池匹配 |
| 折返段叠线 | 同一段路走两遍，App 显示叠线与端点掉头 | 需求本身；编辑器提前用橙色虚线显示折返段 |
| 折返路线采样补偿 | 整秒采样切角后补偿段若直线跳回起点，会产生画外坐标并难以收敛 | 协议仅对开放等长折线沿原路继续补偿（2026-11-16）；dry-run 验证弦长精确、点全在手画线上 |
| 允许打卡点整栋建筑 | 路线可在建筑内绕行 | 超过 30 m 连续在允许建筑内时警告；后续可只放行 2 m 通道 |
| 手画路线质量 | 急弯、自交、顶点过密 | 保存前校验/抽稀；必要时加自交警告 |
| 路线库含校园坐标 | 隐私 | 文件 gitignore，只存本地 |
| 点位/UUID 过期（两阶段方案） | 提交失败 | 优先 provider 回调，避免两阶段（已于 2026-11-13 接入） |
| AMap 瓦片服务不可用/限流 | 底图加载失败 | 本地瓦片缓存 + 矢量兜底；瓦片只作背景，不影响校验 |
