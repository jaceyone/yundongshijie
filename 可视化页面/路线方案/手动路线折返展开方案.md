## 0. 一句话

手画路线就是提交轨迹的唯一几何来源：路线短于目标距离时，沿**原路反向折返**补足，不再用「终点→起点」直线闭环，也不生成任何新手画折线之外的坐标。

## 1. 背景与证据

### 1.1 现象

2026-11-16 的真实提交 `rrid 1366205871`（3000 m 档、实际目标 3050 m）在官方 App 上出现一条斜穿西篮球场的绿线，与路线库里手画的蓝色路线不一致。

### 1.2 复现数据

| 项 | 值 |
| --- | --- |
| 路线库条目 | `2e6dfc8e…`（`points_key 966b7a43…`），2026-11-16 10:45:19 保存 |
| 手画路线 | 27 个顶点，GCJ-02，**2637.6 m** |
| 终点 → 起点 | **113.5 m**（终点在开拓路与南北路交叉口北侧，起点在开拓路西侧 P1） |
| 目标距离 | 3050 m |
| 旧展开结果 | 2637.6（手画）+ **113.5（斜线）** + 298.9（沿路线再跑一段） |
| 提交轨迹 | 441 点，3050.0 m；与「手画 + 旧展开」最大偏差 3.2 m |

结论：坐标、点集、路线库命中都没有错；斜线来自展开算法本身。

### 1.3 根因

`电脑一键启动/route_library.py:218 expand_polyline_to_distance()` 在路线短于目标时，先追加 `(终点 → 起点)` 直线，再沿路线重复。编辑器把它画成橙色虚线（`route_editor.py:1317`），但画在蓝线下面，只有不与蓝线重叠的斜线可见。

## 2. 需求与不变量

**需求**

- R1 提交轨迹只由手画折线构成；不要求首尾重合，不自动闭环。
- R2 路线短于目标时，补足部分只能沿手画折线来回走。
- R3 总里程仍精确等于目标距离。
- R4 5 个官方打卡点仍必须精确经过，顺序沿用路线顺序。
- R5 建筑/边界校验仍然生效；不合法路线不提交。
- R6 官方 App 出现叠线与端点掉头属于预期结果，不是缺陷。

**不变量**

- 不新增手画折线之外的坐标（唯一例外：目标距离处的插值终点，位于折线上）。
- 协议层：`sample_route` 仅对“长度≈目标的开放折线”增加折返补偿分支；`check_track` / 指标 / 签名 / OBS 链路全部沿用（实施时确认，见 §5.5）。
- 路线库存储的仍是模板折线，不改数据格式，不做迁移。
- OSM 自动路线不受影响（它本来就是闭环）。

## 3. 行为定义

### 3.1 术语

- **趟（leg）**：沿手画路线正向或反向完整走一次，长度 = `L`。
- **折返段**：第 2 趟及以后与手画折线重合的反向/正向部分。
- 目标距离需要 `T / L` 趟。

### 3.2 展开规则

设手画折线 `P = [p0 … pn]`，长度 `L`，目标 `T`：

| 条件 | 结果 |
| --- | --- |
| `T ≤ L` | 截断到 `T`（沿用现状） |
| `L < T` | `p0 → pn → p0 → pn …`，按路程精确停在 `T` |

正向首趟按用户画线方向；到达端点后 180° 反向，不画转弯弧线。

### 3.3 边界情况

| 情况 | 行为 |
| --- | --- |
| 折线少于 2 个点 / `L = 0` | 原样返回 |
| `T = L` | 原样返回 |
| `L < T < 2L` | 正向全趟 + 反向 `T-L` |
| `T = 2L` | 终点回到起点（采样层会去掉首尾重复点，由环回补上） |
| `T = k·L` | 端点结束，方向由 k 的奇偶决定 |
| 连续重复顶点 | 展开前先去重（现状） |
| `T` 极大 | 沿用迭代上限并提示「趟数过多」；不改变几何 |

### 3.4 与旧行为对比

| | 旧 | 新 |
| --- | --- | --- |
| 不足里程 | 终点→起点直线 + 重复 | 沿原路反向 |
| 新坐标 | 直线弦上的任意点 | 仅目标距离处的插值点 |
| App 显示 | 一条没画过的斜线 | 原路叠线 + 端点掉头 |
| 校验几何 | `traversal_points` 单独实现 | 与展开同源 |

## 4. 算法

### 4.1 伪代码

```python
def expand_polyline_to_distance(polyline, target):
    pts = dedupe(normalize(polyline))
    if len(pts) < 2:
        return pts
    L = polyline_length(pts)
    if L <= 0:
        return pts
    if target <= L + 1e-9:
        return truncate(pts, target)          # 现状不变

    result, need, forward = list(pts), float(target) - L, False
    guard = 0
    while need > 1e-9 and guard < 200000:
        seq = pts[1:] if forward else list(reversed(pts[:-1]))
        for point in seq:
            seg = distance_m(result[-1], point)
            if seg <= 1e-9:
                continue
            if seg >= need:
                result.append(interpolate_point(result[-1], point, need / seg))
                return result
            result.append(point)
            need -= seg
            guard += 1
        forward = not forward
    return result
```

要点：

- 反向时从 `pts[-2]` 开始追加，不重复终点，避免零长段。
- 最后一趟用 `need / seg` 插值，总长精确等于 `T`（容差 1e-6）。
- 不引入任何新顶点（除插值终点）。

### 4.2 性质

1. **几何封闭**：展开结果任意点到原折线的距离 ≤ 1e-6 m。
2. **长度精确**：`polyline_length(expanded) = target`。
3. **连续**：相邻点之间没有跳变，掉头点只出现一次。
4. **确定性**：同一输入输出固定。
5. **兼容**：`target ≤ L` 的结果与现状完全一致。
6. **首趟方向**：与手画方向一致。

### 4.3 复杂度

时间 `O(n + (T/L)·n)`，空间 `O((T/L)·n)`；沿用 `guard = 200000` 防止异常输入。

### 5.5 协议层（实施时新增，偏离「不改」）

原方案假设「把长度 = 目标的展开折线交给协议」就够了。dry-run 证明不够：`_sample_track` 按 `route[edge % len(route)]` 把折线当闭环，整秒采样切掉拐角后补偿循环要多走 1–3 m，对开放折线会从终点**直线跳回起点**，而且固定点迭代在折返几何上震荡（3050 m 目标弦长只到 3047 m，3056 m 配置到 3064 m），`check_track` 会直接失败。

实际改动（`running/consistency.py`，已获用户确认）：

- `_is_foldback_route()`：长度≈目标（±0.5 m）且首尾不重合才进入折返分支；
- `_foldback_point()` / `_extend_for_foldback()`：沿展开折线里已有的同一直线段继续 61 m（`FOLDBACK_MARGIN_M=60` + 1 m 余量），作为补偿采样点，点在原折线上；
- `_solve_foldback_traverse()`：从目标距离向外扫描第一个弦长命中（±0.02 m）的补偿距离，变号处局部二分；
- OSM 闭环、自由跑合成路线仍走原逻辑，不受影响。

未改上传字段、`check_track`、时间轴整秒规则、指标、签名、OBS、结算。详细记录见 `协议/修改记录.md`。

> 可选手工加固（默认不做）：协议 `client.py` 手动分支校验折线长度必须等于目标（±0.5 m），避免未来调用方漏掉展开。

## 11. 风险与取舍

| 风险 | 说明 | 处理 |
| --- | --- | --- |
| 叠线观感 | 同一段路走两遍 | 需求本身的结果；编辑器提前显示折返段 |
| 掉头处低速点 | 相邻采样点距离很小 | dry-run 检查；若出现 0 秒差再评估采样层，不在本方案内改协议 |
| 服务端方向反转 | 是否接受反向轨迹未知 | 一次受控提交验证 |
| 短路线多次折返 | 300 m 路线跑 3000 m 要 10 趟 | 沿用「趟数偏多」提示，不禁止 |
| 旧条目含返回段顶点 | 旧 `auto_repair` 可能写入过 | 不自动清理；用户重画 |

## 12. 不做的事

- 不画转弯弧线、不做掉头缓冲段（都是新几何）。
- 不为了「看得清」把折返段横向偏移几米（偏移只用于编辑器预览）。
- 不改协议的上传字段、`check_track` 与时间轴；只对“长度≈目标的开放折线”增加折返补偿分支（见 §5.5），其它路线行为不变。
- 不迁移路线库数据、不自动删除旧条目中的点。
- 不恢复「路线必须闭环」的任何校验。
- 不改 OSM 自动路线。
