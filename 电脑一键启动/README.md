# 校园跑 · 电脑一键启动

> 在 Windows 电脑上双击一个按钮，自动完成「登录 → 自动极验 → 提交跑步」。
> 本目录是独立工具，只调用 `协议/7.3.92`，不单独维护协议副本，也不影响主 APK 方案。

## 一句话

现有 Python 协议已经能自动解极验；这个工具只是给它套一个 Tkinter 单窗口和桌面快捷方式，账号密码写死在本地 `config.json`。

## 快速开始

### 1. 填写账号密码

第一次运行 `一键跑步.pyw` 会自动从 `config.example.json` 生成 `config.json`。
也可以手动复制：

```text
config.example.json  →  config.json
```

然后编辑 `config.json`：

```json
{
  "username": "你的手机号",
  "password": "你的密码",
  "distance": 3000,
  "time_sec": 1060,
  "mode": 1,
  "route_mode": "osm",
  "dry_run_default": false,
  "confirm_before_submit": true,
  "campus": "xuchang_280173698",
  "node_path": "",
  "chromium_path": ""
}
```

### 2. 环境自检

在 `电脑一键启动` 目录打开终端：

```bash
python 环境自检.py
```

想验证“自动极验真的能解”，加 `--deep`（只解验证码，不登录、不提交）：

```bash
python 环境自检.py --deep
```

### 3. 先演练，再正式跑

双击 `一键跑步.pyw`：

1. 勾选 **「演练模式（只登录，不提交成绩）」**；
2. 点 **「开始跑步」**；
3. 看到「演练完成 · 未提交成绩」说明登录和自动极验都正常；
4. 取消勾选，再点一次，才会真正提交成绩。

### 4. 创建桌面快捷方式

在 `电脑一键启动` 目录执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\create_shortcut.ps1
```

桌面会出现「校园跑一键启动」，双击即可。

也可以手动：右键 `一键跑步.pyw` → 发送到 → 桌面快捷方式。

## 配置文件说明

| 字段 | 说明 |
| --- | --- |
| `username` | 手机号 |
| `password` | 密码（明文，只保存在本地） |
| `distance` | 目标距离（米），默认 3000；只要求不低于学校 `min_distance`，**允许超过 `day_goal` / 3000** |
| `time_sec` | 目标时长（秒），默认 1060 = 17:40 |
| `mode` | `1` 计分跑；`6` 自由跑（内部合成轨迹） |
| `route_mode` | `osm`（默认，OSM 避建筑）/ `manual`（手动路线库） |
| `dry_run_default` | 打开窗口时是否默认勾选演练模式 |
| `confirm_before_submit` | 正式提交前是否弹确认框；设为 `false` 后点「开始跑步」直接提交，真正一键 |
| `campus` | 可选；OSM 校园数据 id，默认 `xuchang_280173698` |
| `node_path` | 可选；Node 不在 PATH 时填完整路径，例如 `D:/学习2/node.exe` |
| `chromium_path` | 可选；需要指定 Chrome/Edge 可执行文件时填写 |

> JSON 里的 Windows 路径建议用正斜杠 `/`，或者用双反斜杠 `\\`。

## 它是怎么工作的

```text
一键跑步.pyw（Tkinter）
  → runner.py
      ├─ 读取 config.json
      ├─ 预检 Node / Playwright / Chromium / 协议目录
      ├─ SportClient792()
      ├─ client.login(username, password)     ← 自动极验
      │     └─ GeetestV4Solver → Node → Playwright → Chromium
      ├─ anchor_points.select_anchor()        ← 登录前随机选 1 个取点锚点
      ├─ client.execute_run(distance, time_sec, mode, campus, anchor_gcj)
      │     ├─ 计分跑：取当天 5 点 → 官方排序 / 手动路线 / OSM 避建筑
      │     └─ 上传前建筑/边界校验
      └─ 结果写回 UI + logs/YYYYMMDD-HHMMSS.log
```

- 自动极验没有新增依赖：复用仓库里已有的 `login/node_modules/playwright` 和本机 Chromium。
- 首次运行会生成 `device_id`，之后固定使用，避免每次都被服务器识别成一台新设备。
- 登录、规则、轨迹、OBS、结算、回查全部走现有 `协议/7.3.92`。
- 计分跑（`mode=1`）固定使用 OSM 避建筑路线；OSM 规划失败会直接报错、不提交，不会回退到 5 点直线轨迹。
- 自由跑（`mode=6`）没有官方打卡点，仍使用协议内部的合成轨迹。
- 桌面工具不单独改协议；手动路线与锚点取点依赖 `协议/7.3.92` 里已接入的 `route_provider` / `anchor_gcj` 钩子。

## 手动路线库

> 当前状态：路线库/校验/点位采集/编辑器/自动展开/自动修复/路线库管理页已实现；协议侧 `route_provider` 已接入。手动画线只在「开始跑步」登录并取得当天官方点位后进行，保存后自动继续提交。

### 1. 路线库自检（不联网）

```bash
python route_library.py --self-test
```

覆盖：点位 key 顺序无关、EPS 5 m 匹配、原路折返展开、过密顶点去重、同点位多长度变体、真实校园道路段校验。

### 2. 官方 5 点采集（只读，需要登录）

先测量「同一组 5 点」到底有多稳定，再决定是否值得投入画线 UI：

```bash
python route_sampler.py --runs 3 --yes
```

- 只调用取规则/围栏/点位接口，不生成轨迹、不提交成绩。
- 官方 5 点接口 **5 分钟内最多取 3 次**（`10603`）；默认遇到限流就停止。需要更多样本时加 `--wait-limit`，程序会等 300 秒再继续。
- 会登录账号；官方有单设备保护，手机端可能被顶掉或返回 `10121`。
- 报告写到 `logs/points-*.json`，包含校园坐标，不要公开分享。
- 输出：唯一 5 点集合数、重复命中率、同集合点位抖动、顺序变化种类。

### 3. 查看路线库

```bash
python route_library.py --list
```

路线库默认在 `route_library.json`，运行历史在 `route_history.jsonl`，两者都已 gitignore。

### 4. 管理路线库（界面）

主窗口「路线来源」右侧点 **「管理路线库」**（运行中不可用）：

- 按 5 点集合分组列出所有变体，显示长度、在当前目标距离下的趟数、状态、经过顺序、备注、创建/最近使用。
- 选中变体后可 **编辑路线**（进入地图编辑器，保存时覆盖原条目，不新增变体）、**改备注**、**重新校验**、**删除**；双击变体直接编辑。
- 目标距离取 `config.json` 的 `distance`，与提交时一致，编辑器内只读；低于学校最低里程时无法保存。
- 「重新校验」使用该条目保存时的目标距离，不会因为改了 `config.json` 就把合法路线标成不可用。
- 所有改动都会追加到 `route_history.jsonl`（`update` / `notes` / `delete`）。

### 5. 画路线（只在开始跑步后进行）

- 主窗口只保留「路线来源：OSM 自动 / 手动路线库」，没有独立的「画路线」按钮。
- 手动模式下点「开始跑步」后：登录 → 自动极验 → 取**当天**官方 5 点 → 才打开画线器。
- 画完并保存后，编辑器把展开后的折线交回协议，**自动继续生成轨迹/OBS/提交**；不会停在「已保存」。
- **命中只看 5 点位置**：当天的 5 点与库中 5 点相同（5 m 内、顺序无关）就命中，不再要求状态、长度、趟数或重新校验；命中后弹确认框可选「使用」或「重画」。
- 路线比目标短时沿原路反向折返展开；比目标长时，截断后仍覆盖全部 5 点才提示「将截断」并直接使用，否则提示命中但无法直接使用并打开编辑器。
- 绘画线器使用的点位来自本次运行，**不再读取 `logs/points-*.json` 的旧采样快照**。
- **底图是高德地图官方瓦片**（标准/卫星可切换），不是本地自绘地图；瓦片缓存在 `cache/amap/`，带 `© 高德地图` 署名。Pillow 缺失或离线时才回退本地矢量底图。
- 编辑器支持加点/拖点/删点、缩放/平移、吸附打卡点、聚焦点位、折返段的橙色虚线预览（画在蓝线之上），以及保存前自动修复/校验。
- 以后要临时离线画图，仍可用命令行打开编辑器（只预览/存库，不参与本次提交）：

```bash
python route_editor.py --latest-sampler --target 3000
```

### 6. 设计约束

- 手画路线是**开放折线**，不要求闭环；条件为「路线长度 ≤ 目标距离」。- 路线短于目标时，脚本**沿已画路线原路反向折返**补足到目标距离（例如 962 m 模板 → 3000 m 轨迹，为 3.12 趟：正向 1 趟 + 折返 2.12 趟），不生成手画折线之外的坐标；折返段在编辑器里以橙色虚线画在蓝线之上，并纳入校验。
- 交给协议的折线长度已经等于目标；协议整秒采样的补偿段沿原路继续（2026-11-16 协议折返分支），不会从终点直线跳回起点。
- 5 个官方点必须是路线上的精确顶点（0.1 m），否则 `check_track` 会失败。
- 校验/保存会**自动修复**：缺失打卡点（必要时用 A* 绕行到点）、超长截断、过近重复顶点、与上一保留顶点间距 <3 m 的过密顶点（打卡点与首尾保留）；穿建筑/越界段**不再自动绕行**，直接提示「第 N 段穿建筑/边界，请重画」。
- 同一点位集可存多条不同长度路线；命中后优先选长度装得下目标的变体，装不下时提示截断或重画。
- **目标距离只要求不低于学校最低里程**（当前 1000 m）；允许超过 `day_goal` / 3000 m。编辑器目标距离只读，画线/保存会按目标距离展开；runner 与协议侧都只校验下限，不设 3000 m 硬上限。
- 编辑器里的「目标距离」来自本次运行配置，不能在编辑器里改大；实际提交距离仍由 `config.json` 的 `distance` 决定。
- 底图使用高德地图官方瓦片（标准/卫星）；Pillow 缺失或离线时回退本地矢量。
- 完整方案见 `可视化页面/路线方案/手动路线与路线库方案.md`。

## 直角路线（拐角≈90°）

> 2026-11-21 新增。手动路线库是手画的平滑折线，短了会原路折返（180° 掉头）；OSM 走的是道路中心线，拐角是弯的。两者都不是「沿路走、路口拐直角」的样子。

做法：在 `协议/7.3.92/running/data` 的校园代价栅格（2 m/格）上**只走东西/南北**铺线：

- 官方 5 点之间用四邻域 A*（带拐弯惩罚，尽量走直），打卡点原坐标作为顶点保留（0.1 m）；
- 长度不够时在外面套一个**矩环**（矩形四边，四个 90° 角），环的大小用二分搜索，取「≤ 目标距离」的最大装法；
- 折线简化后拐角全部 90°；短促的 180° 回冲点会被删掉（删完不能变差、不能少走打卡点）；
- 出线前用协议同一套 `TrackPlanner.validate_track` 做穿建筑/越界校验，再用 `sample_route` 做整秒采样模拟。

命令：

```bash
python rect_route.py --route-id 46bfd856 --target 3056 --time 1222   # 离线预演 + PNG
python rect_plan.py --config config.json                            # 只读取点（复用 token）
python run_rect.py --config config.json --stop-after-preflight      # 登录+取点+铺线+采样，不提交
python run_rect.py --config config.json                             # 预演后直接提交
python run_rect.py --config config_b.json --use-session             # 复用 session_b.json 的 token 提交
```

- `--use-session` 不重新登录，专治 `10121 此账号已在其他设备登录`（2026-11-21 B 号就是被它挡住，改用旧 token 提交成功）。
- `--auto-anchor` 预演时自动换取点锚点（最多 3 个）：官方 5 点偶尔会落在「禁走格但不在建筑轮廓里」的缓冲带（2026-11-22 A 号的「教学楼2」），这组点位无论如何都过不了校验，换一组最省事。
- **默认往校园中心跑**：锚点按到校园中心的距离排序（a2 41 m、a4 104 m 最近），矩环中心 = 75% 校园中心 + 25% 官方点质心；要恢复旧行为用 `--no-center-first`。
- 每次提交都会把路线图 `logs/run-rect-<尾号>-<时间>.png` 和 `logs/run-rect-*.json` 落盘，肉眼确认拐角。
- 路线以 `route_provider` 形式交给协议，不改 `协议/7.3.92` 任何文件。

## 取点锚点池

> 当前状态：已实现（桌面端）。协议侧取点接口支持指定锚点；桌面端支持画 1–5 个锚点、每次随机选 1 个、路线库未命中时三选一。尚未执行真实取点实验。

官方 5 点接口本身就接收 `latitude/longitude`；以前脚本固定用围栏第一个顶点，所以取点位置一直是同一片区域。锚点池把「从哪取点」交给用户：

- 在地图上画 **1–5 个锚点**（推荐 5 个），保存到 `anchor_points.json`（GCJ-02，已 gitignore）。
- 每次正式运行（计分跑、非演练）在登录前随机选 **1 个**；首版**不避重**，允许连续两次选到同一个锚点。
- 锚点只作为官方取点接口的当前位置；**官方返回哪 5 点仍由服务端决定**，客户端不伪造点位。
- 选中的锚点显示在确认框和日志里，并写入路线库历史（只追溯，不参与匹配）。

### 入口

主窗口「路线来源」下方新增「取点位置」行：

- 没有锚点：`取点位置：未配置（使用围栏顶点）  [设置取点锚点]`
- 已有锚点：`取点位置：随机（A1–A5） · 上次 A3 教学楼  [编辑锚点]`

点按钮打开地图编辑器（高德瓦片/本地矢量）：

- 左键点击添加、拖动移动、右键删除；右侧列表可定位、改名、删除；
- 最多 5 个；保存前校验是否在校园允许边界内；在建筑内或两点相距 < 100 m 只警告、不阻止；
- 保存后提示「下次运行生效」。

### 路线库未命中时

取点完成后先按 5 点位置查路线库：

- 命中 → 复用已有路线（现有流程）；
- 未命中 → 弹三选一：**手动画线 / OSM 自动规划 / 取消**；
  - 三者都复用**同一次**取点结果，不会再请求 5 点接口（官方限 5 分钟 3 次）；
  - 对话框显示本次锚点、5 点名称、`points_key` 前 10 位，并说明「这不是错误」；
  - 「OSM 自动规划」走现有官方排序 + OSM 避建筑；失败直接报错；
  - 「取消」不提交、不写 outbox，返回 `manual_route_cancelled`。

### 自检与独立运行

```bash
python anchor_points.py --self-test   # 读写/校验/随机选择/空池回退
python anchor_editor.py               # 单独打开锚点编辑器
```

### 注意

- 锚点必须在官方围栏内；保存时的校园边界只是近似，运行时协议会再用官方围栏校验，越界则不发取点请求。
- 保存锚点时尚未登录，`unid` 会从最近一次取点报告推断；推断不到时留空，不影响运行（`campus` 已记录）。
- 锚点不做「刷新到出现满意点集」的自动循环；官方短时间内可能返回同一组点，属正常现象。
- 锚点与轨迹起点**不强制相同**（已确认）；轨迹仍按官方 5 点与路线生成。

## 排错

### 双击没反应 / 看不到错误

用命令行启动，错误会显示在控制台：

```bash
python 一键跑步.pyw
```

### `Node.js` 检查失败

- 安装 Node.js，或
- 在 `config.json` 里填：

  ```json
  "node_path": "D:/学习2/node.exe"
  ```

### `Playwright` / `Chromium` 检查失败

在仓库根目录执行：

```bash
cd 协议/7.3.92/login
node node_modules/playwright/cli.js install chromium
```

然后重新运行：

```bash
python 环境自检.py
```

### 自动极验失败

1. 先跑 `python 环境自检.py --deep`，确认单次识别是否成功；
2. 确认网络能访问极验；
3. 再点一次「开始跑步」，协议内部会重试；
4. 仍然失败时看 `logs/` 里最新日志的 `STDOUT/STDERR`。

### 网络超时 / 「请求过于频繁」

日志里出现 `TimeoutError: The read operation timed out`，或提示「距上次运行结束仅 … 秒」，是上游加速节点在限流，不是本机断网：

- 实测 `checkGeeUse` / `geevalidate` 会被压到整 20 秒才返回，偶尔直接断连；
- 网关域名会轮换多个边缘 IP，个别节点会出现「TCP 连上、TLS 卡约 19 秒后断开」；客户端会逐地址完成 TCP + TLS（单地址 4 秒），并在进程内缓存最近可用节点 5 分钟；
- 客户端单次超时已放宽到 35 秒；只读预检（`checkGeeUse` / `geevalidate`）与 OBS 预签名申请自动重试，`/login` 与成绩结算超时**不自动重试**（结果未知，避免重复成绩；先到官方 App 确认）；
- 两次运行之间强制冷却 60 秒；脚本或自动化需要跳过时设环境变量 `CAMPUSRUN_SKIP_COOLDOWN=1`。

等待 5–10 分钟再试，不要连续点击「开始跑步」。

### 登录返回 `10121`

账号单设备保护。不要在手机和电脑上同时登录同一账号；先在另一端退出，或等一段时间再试。

### 登录返回 `10175`

手机号或密码错误。连续 3 次失败会锁定 1 小时；不要靠在 `config.json` 里反复改密码试探，先用官方 App 确认能正常登录。

### 提交成功但显示「未达标」

说明服务器判定配速/步频/点位等条件未通过。看日志里的 `reasonList` 或到官方 App 查该 `rrid` 的详情。

### Tkinter 缺失

Windows 安装 Python 时勾选 **tcl/tk and IDLE**；或重新安装 Python。

### 杀毒软件拦截

Playwright 的 Chromium 可能被误报。把 `%LOCALAPPDATA%\ms-playwright` 加入信任目录。

## 安全提醒

- `config.json` 是**明文密码**，只放在本机；已加入 `.gitignore`，不要提交、截图或发给别人。
- `logs/` 里有 uid、unid、rrid 和运行轨迹信息；不要公开分享完整日志。
- 本工具只用于你自己的账号与设备。
- 第一次使用请务必先勾选演练模式，确认不会误提交。
